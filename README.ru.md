# tgsync

Сессии агента Claude Code на твоих машинах с управлением из Telegram. Ставишь задачу с телефона, следишь за работой, отвечаешь на вопросы агента, одобряешь команды, смотришь diff и коммитишь. Сама работа идёт на твоём компьютере — с твоими плагинами, skills и hooks.

Каждая машина с tgsync — **нода** со своим ботом. Все ноды работают в одной Telegram-группе с темами:

- у каждой ноды есть тема управления `🖥 <имя ноды>` с закреплённой карточкой;
- у каждой сессии агента — своя тема.

## Зачем

Claude Code лучше всего работает на настоящей машине — с твоими репозиториями, инструментами и доступами. Но долгой задаче не нужно, чтобы ты сидел за клавиатурой. tgsync оставляет агента там, где лежит код, и переносит в Telegram только разговор: начинать, направлять и проверять работу можно откуда угодно, а каждое рискованное действие всё равно ждёт твоей кнопки.

## Возможности

**Сессии**
- Новые проекты и сессии из Telegram, у каждой сессии своя тема; продолжение после сбоя или перезапуска.
- Живой статус хода: время, число шагов, текущее действие, последняя реплика агента.
- Очередь сообщений с реакцией 👀 и кнопкой «Отправить сейчас»; лимит параллельных сессий, один ход на проект.
- Остановка хода, смена режима Claude Code (`default`, `acceptEdits`, `plan`), закрытие сессии.

**Разрешения**
- Запросы разрешений кнопками: разрешить один раз, отклонить или «Всегда» с намеренно узкими правилами.
- Режимы автоодобрения для всей ноды: спрашивать всё, всё кроме sudo, всё сам.
- Вопросы агента (`AskUserQuestion`) кнопками, с мультивыбором и своим ответом текстом.
- `sudo` через Telegram: одобрение каждой команды, пароль из `.env` или из чата с немедленным удалением.

**Итоги хода**
- Итог хода со списком изменённых файлов и статистикой `+/-` по строкам.
- Diff всего хода файлом, коммит руками агента, откат к состоянию до хода с подтверждением.
- Файлы в обе стороны: агент присылает написанные документы, ты отправляешь файлы и скриншоты.
- Просмотр файлов проекта `/ls` и `/file` для любого файла.

**Наблюдение**
- Панель субагентов: кто работает, над чем, кто вызвал; остановить агента или получить его полный ответ.
- Заполненность контекста и сжатие одной кнопкой; расход токенов по сессии и по ноде; предупреждения о лимитах подписки.
- `/history`: продолжить любую сессию Claude Code из терминала или приложения (копией, если она ещё активна).

**Ещё**
- Голосовые через свой сервер распознавания речи; агент пересказывает задачу и ждёт «да».
- Профили плагинов для проекта или отдельной сессии.
- Порядок в группе: закреплённая карточка ноды, самоочистка темы ноды, уборка старых тем с подтверждением, свой цвет тем у каждой ноды.
- Linux (systemd), macOS (launchd) и Windows (Планировщик заданий); по желанию Docker.

## Как это устроено

```mermaid
flowchart LR
    you["Ты<br/>(Telegram)"] <--> tg["Группа<br/>с темами"]
    tg <--> nodeA["нода tgsync A<br/>(бот A)"]
    tg <--> nodeB["нода tgsync B<br/>(бот B)"]
    nodeA <--> claudeA["claude CLI<br/>(Agent SDK)"]
    claudeA <--> projA["проекты в<br/>PROJECTS_ROOT"]
    nodeA --- dbA[("SQLite")]
    nodeA -. голосовые, по желанию .-> stt["свой STT-сервер"]
```

Нода — один бинарник на Go. Она получает обновления своего бота через Telegram Bot API, запускает по процессу `claude` на каждую активную сессию через Go-клиент протокола Claude Agent SDK, отвечает на запросы разрешений агента кнопками в Telegram и хранит состояние (сессии, правила, расход) в локальной базе SQLite. Ноды не общаются друг с другом, у них общая только группа.

## Требования

- Linux, macOS или Windows 10/11.
- Установленный и авторизованный [Claude Code](https://docs.claude.com/en/docs/claude-code) (`claude` в `PATH`). На Windows нужен нативный `claude.exe` и Git for Windows.
- Go (версия из `go.mod`) для сборки из исходников.
- Telegram-группа с включёнными темами и по боту на каждую ноду.

## Быстрый старт

1. Установи Claude Code и войди в него на этой машине.
2. Создай бота в [@BotFather](https://t.me/BotFather) и скопируй токен.
3. Создай группу, включи **Темы**, добавь бота администратором с правом «Управление темами» (для всех возможностей — ещё «Удаление сообщений» и «Закрепление сообщений»).
4. Склонируй репозиторий и заполни `.env`: токен бота, свой user_id, id группы (начинается с `-100`, например `-1001234567890`), `PROJECTS_ROOT`.
   ```bash
   cp .env.example .env
   ```
5. Проверь установку: `make check`.
6. Установи сервис: `make install` (перенесёт `.env` в папку ноды, на Linux это `~/.config/tgsync`). На Windows — `scripts/install.ps1`.
7. Открой в группе тему `🖥 <NODE_NAME>`, напиши `/menu`, затем `/new myproject твоя задача`.

Подробно, включая macOS, Windows, Docker и сервер распознавания речи: [docs/ru/setup.md](docs/ru/setup.md).

## Релизы

При пуше тега `v*` GoReleaser собирает архивы для Linux, macOS и Windows (amd64 и arm64) и прикладывает их к черновику релиза на GitHub, который публикуется вручную. Образы контейнеров не публикуются: `Dockerfile` собирает образ локально. Собрать из исходников можно всегда.

## Безопасность

Кто управляет ботом, тот запускает агента от твоего пользователя ОС. Управлять нодой могут только id из `ALLOWED_USER_IDS`, а вывод агента видят все участники группы — держи группу закрытой. По умолчанию каждое рискованное действие ждёт кнопки; режимы автоодобрения эту защиту снимают. Сообщения проходят через серверы Telegram и не шифруются end-to-end. Кроме Telegram и самого Claude Code, tgsync не обращается ни к каким сторонним сервисам; распознавание речи работает на твоём сервере. Прочитай [docs/ru/security.md](docs/ru/security.md), прежде чем включать автоодобрение или sudo. Об уязвимостях сообщай приватно, как описано в [SECURITY.md](SECURITY.md).
