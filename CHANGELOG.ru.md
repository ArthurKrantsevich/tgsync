# Журнал изменений

Все заметные изменения проекта описываются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют [семантическому версионированию](https://semver.org/lang/ru/spec/v2.0.0.html).

English version: [CHANGELOG.md](CHANGELOG.md).

## [Unreleased]

### Исправлено

- `tgsync check`, `version`, `run` и `profile` работают, когда их запускает агент (например, `make install` из сессии): окружение агента больше не переводит каждый вызов tgsync в режим askpass для sudo.
- `tgsync version` у сборки из исходников показывает версию из git (`v0.3.0`, `v0.3.0-2-gabc123`) вместо `dev`.

## [0.3.0] - 2026-09-26

Английский интерфейс и более тихое автоодобрение. Обновление: распакуй новый архив и снова запусти скрипт установки. Чтобы оставить русский интерфейс, до перезапуска добавь `BOT_LANGUAGE=ru` в `.env`, затем выполни `tgsync profile`.

### Добавлено

- **Английский интерфейс.** Все сообщения, кнопки, всплывающие ответы и меню команд бота, описания бота и группы, `tgsync check`, ошибки конфигурации, сообщения askpass для sudo и скрипты установки и удаления теперь есть на английском и русском. Язык выбирает `BOT_LANGUAGE` в `.env`: `en` (по умолчанию) или `ru`. Неизвестное значение показывает `tgsync check`.
- **Единый каталог строк** (`internal/i18n`). Тесты падают, если нет одного из языков, если у языков разные спецификаторы формата, если код использует неизвестный ключ или в каталоге остался неиспользуемый.
- Английские скриншоты в README и английские подписи кнопок во всех английских гайдах.

### Изменено

- **Язык интерфейса по умолчанию теперь английский — задай `BOT_LANGUAGE=ru`, чтобы оставить русский.**
- **Тихое автоодобрение.** В режимах 🟢 и 🟡 бот больше не пишет заметку «✅ авто» о каждой команде. Строка статуса показывает описание от агента («▶ Прогоняю тесты») вместо самой команды. sudo и деструктивные команды (удаление и перемещение файлов, `chmod`, остановка процессов, `systemctl`, `git push`/`reset`/`clean`/`checkout`, `git branch -D`, `docker rm`/`prune`, оболочки, `eval`, `xargs`, команды, которые не разбираются) по-прежнему оставляют тихую заметку с описанием и командой.
- Агента просят описывать каждую команду на языке пользователя: что делает и зачем.

### Исправлено

- Русские склонения: «2 файла», «Удалить 1 тему?», «Откачено 2 файла» вместо «2 файлов», «1 тем» и голого числа.
- Сессия, у темы которой ещё заголовок по умолчанию, переименовывается по первому сообщению и после смены `BOT_LANGUAGE`.

## [0.2.1] - 2026-09-26

Исправления безопасности и надёжности. Обновление: распакуй новый архив и снова запусти скрипт установки.

### Безопасность

- **Пароль sudo мог попасть к агенту.** Команда могла задать свой `SUDO_ASKPASS`, и sudo отдал бы одноразовый токен этой программе. Теперь в каждый одобренный вызов sudo подставляется askpass самого tgsync; команды, которые задают `SUDO_ASKPASS` или `PATH`, объявляют функцию или alias `sudo` или вызывают sudo не из системной папки, отклоняются.
- **Файловые инструменты учитывают ссылки и `~`.** Read, Write, Grep, Glob и остальные раскрывают `~` и симлинки до проверки защищённых файлов, поэтому ссылка на папку tgsync больше не проходит.
- **Bash-команды, добирающиеся до папки tgsync,** ловятся в большем числе написаний: `$HOME`, `~user`, `$XDG_CONFIG_HOME`/`$APPDATA`, относительные пути после `cd`, скрипты в `sh -c` и heredoc с масками или переменными. Команда, которую не удалось разобрать, теперь просит подтверждение.
- **Правила «Всегда» уже.** `git config`, `git -c`, любые `-o`/`--output` и аргументы, указывающие в `.git`, `.claude` и другие чувствительные файлы, одобряются только разово и не покрываются существующими правилами. Имя команды в кавычках (`\rm`, `"rm"`) больше не обходит список разовых.
- sudo в цикле или функции может спросить пароль до 5 раз.

### Исправлено

- **Снимки хода могли сломаться навсегда**, если git остановили посреди снимка (таймаут или остановка ноды) и остался `index.lock`. Старые блокировки удаляются; git сначала просят остановиться штатно; после таймаута нет повторной попытки; при недоступной папке кэша используется временный индекс; побочные индексы, не использованные 30 дней, удаляются.
- После перехваченной паники, если прервать ход не удалось, процесс claude перезапускается, а не получает следующее сообщение, пока занят.
- Паника при обработке таймеров больше не отключает `MAX_TURN_DURATION` для этого хода.
- Меньше ложных подтверждений: сообщения коммита с `/` или `~`, сборка в папку с именем `tgsync`, `ls ..` из проекта в домашней папке.

## [0.2.0] - 2026-09-26

Релиз стабильности и кроссплатформенности: новых команд нет, много исправлений. Обновление: распакуй новый архив и снова запусти скрипт установки — настройки, сессии и база сохранятся.

### Исправлено

- **Итог хода мог пропустить правку.** Если агент менял файл без изменения размера в ту же секунду, в итоге было 0 изменений, а откат считал файл изменённым после хода. Снимки теперь сохраняют «racy»-проверку git.
- **Нода больше не падает от паники в сессии.** Паники в фоновой работе сессии (события агента, отправка файлов, таймеры, панель агентов) перехватываются и пишутся в лог; ход завершается с ошибкой, а нода продолжает работать.
- **Удалённая тема определяется и при правке сообщений.** Если правка вернула «сообщение не найдено», нода проверяет, жива ли тема, и закрывает сессию, если темы нет.
- **Windows:** пути внутри проекта всегда показываются и передаются в git через `/`; файл, подменённый после проверки, отклоняется так же, как на Linux и macOS; панель агентов скрывает самых старых завершённых, когда несколько закончили одновременно; установщик и деинсталлятор останавливают запущенный `tgsync.exe` перед заменой.
- **macOS:** тесты сокета askpass больше не упираются в лимит длины пути 104 байта.
- **Распознавание sudo:** относительный путь вроде `./internal/sudo` в команде больше не принимается за вызов `sudo` через обёртку.
- **Тема ноды:** вывод `/usage` и уведомления о лимитах теперь удаляются через час, как остальные служебные сообщения; подтверждение 🧹 уборки, чьё сообщение уже удалено, больше не выдаёт ошибку и всё равно обновляет карточку.
- **Лимит длительности хода:** если прервать затянувшийся ход (`MAX_TURN_DURATION`) не удаётся, предупреждение повторяется не чаще раза в минуту, а не каждую секунду.

### Изменено

- **Снимки хода быстрее.** Постоянный побочный индекс для каждого репозитория (в папке кэша пользователя) позволяет git не перехешировать неизменённые неотслеживаемые файлы, поэтому большие неотслеживаемые папки больше не тормозят каждый ход. Если снимок всё же не удался, в тему приходит короткое сообщение вместо молча пропавшего итога.
- **Ошибки конфига на английском**, включая ошибки длительностей (`X must be a duration like 30m or 2h`).
- **Релизы** начинаются с инструкции по установке на английском и русском.
- Зависимости: `golang.org/x/sys` 0.48.0; действия CI `checkout`, `setup-go`, `goreleaser-action` v7.

### Безопасность

- `profiles.yaml` и сокет askpass для sudo теперь защищённые файлы, как `.env` и база: агент не может прочитать или изменить их без твоего подтверждения.

## [0.1.0] - 2026-09-26

Первый публичный релиз.

### Добавлено

#### Сессии
- Нода на каждой машине со своим ботом; все ноды работают в одной Telegram-группе с темами.
- Тема ноды `🖥 <нода>` с меню кнопками и командами: `/projects`, `/newproject`, `/new проект [--profile имя] [задача]`, `/sessions`, `/history`, `/profiles`, `/usage`, `/approve`, `/help`; `/control` в общей теме находит или пересоздаёт тему ноды.
- Своя тема на каждую сессию с постоянным названием `проект · задача`; сессия продолжается с полным контекстом после сбоя, остановки по простою или перезапуска ноды.
- Живой статус хода: время, число шагов, текущее действие, действие субагента, последняя реплика агента; кнопка остановки.
- Один ответ на ход с длительностью, числом шагов, стоимостью и заполненностью контекста.
- Очередь сообщений с реакцией 👀 и кнопкой «Отправить сейчас», которая прерывает текущий ход; лимит параллельных ходов на ноде и один ход на проект.
- `/stop`, `/mode default|acceptEdits|plan`, `/close` и свёрнутая панель `⋯` под ответом (файлы, режим, закрытие с подтверждением).
- Остановка процесса по простою, предупреждение о тишине с кнопками «Ждать» и «Остановить», необязательный жёсткий лимит хода, напоминания о неотвеченных запросах.
- Удаление темы в Telegram закрывает сессию; сессии без единого ответа агента удаляются вместе с темой.
- В теме видны MCP-серверы, которым нужно внимание, и сообщения hooks, адресованные пользователю.

#### Разрешения
- Запросы разрешений кнопками: разрешить один раз, отклонить (с причиной следующим сообщением) или «Всегда» для проекта.
- Рядом с командой показывается её описание от агента: видно, зачем она нужна.
- Режимы автоодобрения для всей ноды: по запросу (по умолчанию), всё кроме sudo, всё сам.
- `AskUserQuestion` кнопками: мультивыбор, несколько вопросов подряд, свой ответ текстом или голосом.
- `sudo` через askpass-мост: одобрение каждой команды, пароль из `.env` (`SUDO_MODE=env`) или из темы с немедленным удалением (`SUDO_MODE=telegram`).

#### Итог хода
- Список изменённых за ход файлов со статистикой `+/-` по каждому файлу и в сумме.
- Снимки git до и после хода через временный индекс; индекс, ветки и stash пользователя не меняются.
- Diff всего хода файлом, коммит руками агента в стиле репозитория и откат к состоянию до хода с подтверждением.

#### Файлы
- Агент присылает документы инструментом `send_file`; упомянутые им документы и файлы по маскам `AUTO_SEND_GLOBS` приходят после хода; каждая версия файла приходит один раз.
- `/file путь` и просмотр файлов проекта `/ls` кнопками.
- Документы, фото и скриншоты в теме сессии сохраняются в `.tgsync/inbox/` (исключено из git) и передаются агенту, подпись становится задачей.

#### Голосовые
- Голосовые и аудио распознаются своим OpenAI-совместимым сервером распознавания речи (`STT_URL`); в комплекте compose-файл для локального сервера.
- Агент пересказывает распознанную задачу и ждёт подтверждения, прежде чем начать.

#### Расход и лимиты
- Заполненность контекста в итоге каждого хода, подсказка со сжатием `/compact` одной кнопкой и сообщение о сжатии истории; `/context`.
- `/usage` для сессии (ходы, токены, оценка стоимости) и для ноды (лимиты подписки, расход за сегодня и за 7 дней по проектам).
- Уведомления о лимитах подписки: близко к лимиту, лимит исчерпан, снова доступен — один раз на окно.

#### Субагенты
- Живая панель агентов с деревом вызовов, карточкой агента, кнопкой остановки и полным ответом файлом; `/agents`.
- Фоновые агенты работают после конца хода; их результаты агент разбирает в ходах-продолжениях, которые не занимают слот параллельности. Закрытие сессии останавливает их.

#### История
- `/history` показывает недавние сессии Claude Code из терминала, приложения и бота и подключает тему к любой из них.
- Сессия, которая ещё активна в другом месте, продолжается копией; сессия, уже открытая в Telegram, не открывается второй раз — бот присылает ссылку.

#### Профили
- Профили плагинов в `profiles.yaml`: источники настроек, переменные окружения и поверх-настройки; выбор для сессии, для проекта или по умолчанию; `full` повторяет настройку терминала.
- `/skills` показывает команды и skills агента; незнакомые `/команды` уходят агенту.

#### Порядок в группе
- Закреплённая карточка ноды со счётчиками сессий, временем запуска и кнопками уборки.
- Уборка закрытых тем и тем, упавших без ответа, с подтверждением.
- Чистая тема ноды: остаётся только последнее меню, служебные сообщения удаляются примерно через час, кнопка удаляет их сразу.
- Свой цвет иконок тем у каждой ноды и значки состояния; тема General скрывается один раз; аватар и описание группы ставятся один раз, если их нет; уведомление о недостающих правах администратора.
- `tgsync profile` ставит боту аватар и описания.

#### Платформы и поставка
- Установка и удаление сервиса на Linux (пользовательский сервис systemd), macOS (агент launchd) и Windows (Планировщик заданий).
- `tgsync check` проверяет настройки, права бота в Telegram и CLI `claude`.
- Папка конфигурации по правилам ОС, `TGSYNC_HOME`, `CLAUDE_CLI_PATH` и `TGSYNC_LOG` для лога в файл.
- Dockerfile и compose-файл для запуска ноды в контейнере.
- CI на Linux, macOS и Windows; архивы GoReleaser для Linux, macOS и Windows на amd64 и arm64.
- Повтор запросов к Telegram при ограничении частоты и сбоях сети.

### Безопасность
- Управлять нодой могут только пользователи из `ALLOWED_USER_IDS` и только в её группе и темах.
- Служебные файлы tgsync (`.env`, база и её WAL-файлы) недоступны файловым инструментам, поиску и командам shell с буквальным путём и никогда не отправляются в Telegram.
- Команды shell, которые могут обратиться к папке tgsync в любом написании (`~`, `$HOME`, относительные пути, маски, переменные, вложенные shell, heredoc), требуют кнопки в любом режиме автоодобрения, без «Всегда»; сохранённые правила на них не действуют.
- Запись в файлы, из которых git, Claude Code или shell запускают команды (`.git/`, `.gitattributes`, `.gitmodules`, `.claude/`, `.envrc`, `.mcp.json`, `.vscode/tasks.json`), требует одобрения даже внутри проекта в режиме по запросу; симлинки раскрываются до решения.
- Правила «Всегда» не шире одобренного: команда с первым аргументом, без цепочек; для shell, интерпретаторов, разрушительных команд, обёрток, `ssh`, `sudo` и `git -c` правило не создаётся; правило для файлов действует на одну папку. Старые, более широкие правила больше не действуют.
- Токены sudo одноразовые, привязаны к одобренным вызовам и живут недолго; askpass-сокет отвечает только процессу, чей родитель — настоящий `sudo` с правами root (Linux и macOS); sudo внутри обёрток отклоняется; запрос пароля снимается в конце хода; на Windows sudo выключен.
- Токен бота и пароль sudo убираются из окружения агента; пароль sudo не пишется в логи и базу.
- Проверка «файл внутри папки» учитывает ОС (написания путей Windows и Git Bash, регистр, точки в конце, потоки, жёсткие ссылки); отправляемые файлы читаются через один проверенный дескриптор.
- Паники в обработчиках обновлений перехватываются; скачивание файлов, распознавание речи и чтение истории ограничены по времени или объёму; данные кнопок укладываются в лимиты Telegram; число хранимых кнопок на сессию ограничено; двойное нажатие не создаёт дубликатов сессий и тем.
