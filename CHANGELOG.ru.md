## [0.1.0] - 2026-09-26

Первый публичный релиз.

### Добавлено

#### Сессии
- Нода на каждой машине со своим ботом; все ноды работают в одной Telegram-группе с темами.
- Тема ноды `🖥 <нода>` с меню кнопками и командами: `/projects`, `/newproject`, `/new проект [--profile имя] [задача]`, `/sessions`, `/history`, `/profiles`, `/usage`, `/approve`, `/help`; `/control` в общей теме находит или пересоздаёт тему ноды.
- Своя тема на каждую сессию с постоянным названием `проект · задача`; сессия продолжается с полным контекстом после сбоя, остановки по простою или перезапуска ноды.
- Живой статус хода: время, число шагов, текущее действие, действие субагента, последняя реплика агента; кнопка остановки.
- Один ответ на ход с длительностью, числом шагов, стоимостью и заполненностью контекста.
- Очередь сообщений с реакцией 👀 и кнопкой «Отправить сейчас», которая прерывает текущий ход; лимит параллельных ходов на ноде и один ход на проект.
- `/stop`, `/mode default|acceptEdits|plan`, `/close` и свёрнутая панель `⋯` под ответом (файлы, режим, закрытие с подтверждением).
- Остановка процесса по простою, предупреждение о тишине с кнопками «Ждать» и «Остановить», необязательный жёсткий лимит хода, напоминания о неотвеченных запросах.
- Удаление темы в Telegram закрывает сессию; сессии без единого ответа агента удаляются вместе с темой.
- В теме видны MCP-серверы, которым нужно внимание, и сообщения hooks, адресованные пользователю.

#### Разрешения
- Запросы разрешений кнопками: разрешить один раз, отклонить (с причиной следующим сообщением) или «Всегда» для проекта.
- Рядом с командой показывается её описание от агента: видно, зачем она нужна.
- Режимы автоодобрения для всей ноды: по запросу (по умолчанию), всё кроме sudo, всё сам.
- `AskUserQuestion` кнопками: мультивыбор, несколько вопросов подряд, свой ответ текстом или голосом.
- `sudo` через askpass-мост: одобрение каждой команды, пароль из `.env` (`SUDO_MODE=env`) или из темы с немедленным удалением (`SUDO_MODE=telegram`).

#### Итог хода
- Список изменённых за ход файлов со статистикой `+/-` по каждому файлу и в сумме.
- Снимки git до и после хода через временный индекс; индекс, ветки и stash пользователя не меняются.
- Diff всего хода файлом, коммит руками агента в стиле репозитория и откат к состоянию до хода с подтверждением.

#### Файлы
- Агент присылает документы инструментом `send_file`; упомянутые им документы и файлы по маскам `AUTO_SEND_GLOBS` приходят после хода; каждая версия файла приходит один раз.
- `/file путь` и просмотр файлов проекта `/ls` кнопками.
- Документы, фото и скриншоты в теме сессии сохраняются в `.tgsync/inbox/` (исключено из git) и передаются агенту, подпись становится задачей.

#### Голосовые
- Голосовые и аудио распознаются своим OpenAI-совместимым сервером распознавания речи (`STT_URL`); в комплекте compose-файл для локального сервера.
- Агент пересказывает распознанную задачу и ждёт подтверждения, прежде чем начать.

#### Расход и лимиты
- Заполненность контекста в итоге каждого хода, подсказка со сжатием `/compact` одной кнопкой и сообщение о сжатии истории; `/context`.
- `/usage` для сессии (ходы, токены, оценка стоимости) и для ноды (лимиты подписки, расход за сегодня и за 7 дней по проектам).
- Уведомления о лимитах подписки: близко к лимиту, лимит исчерпан, снова доступен — один раз на окно.

#### Субагенты
- Живая панель агентов с деревом вызовов, карточкой агента, кнопкой остановки и полным ответом файлом; `/agents`.
- Фоновые агенты работают после конца хода; их результаты агент разбирает в ходах-продолжениях, которые не занимают слот параллельности. Закрытие сессии останавливает их.

#### История
- `/history` показывает недавние сессии Claude Code из терминала, приложения и бота и подключает тему к любой из них.
- Сессия, которая ещё активна в другом месте, продолжается копией; сессия, уже открытая в Telegram, не открывается второй раз — бот присылает ссылку.

#### Профили
- Профили плагинов в `profiles.yaml`: источники настроек, переменные окружения и поверх-настройки; выбор для сессии, для проекта или по умолчанию; `full` повторяет настройку терминала.
- `/skills` показывает команды и skills агента; незнакомые `/команды` уходят агенту.

#### Порядок в группе
- Закреплённая карточка ноды со счётчиками сессий, временем запуска и кнопками уборки.
- Уборка закрытых тем и тем, упавших без ответа, с подтверждением.
- Чистая тема ноды: остаётся только последнее меню, служебные сообщения удаляются примерно через час, кнопка удаляет их сразу.
- Свой цвет иконок тем у каждой ноды и значки состояния; тема General скрывается один раз; аватар и описание группы ставятся один раз, если их нет; уведомление о недостающих правах администратора.
- `tgsync profile` ставит боту аватар и описания.

#### Платформы и поставка
- Установка и удаление сервиса на Linux (пользовательский сервис systemd), macOS (агент launchd) и Windows (Планировщик заданий).
- `tgsync check` проверяет настройки, права бота в Telegram и CLI `claude`.
- Папка конфигурации по правилам ОС, `TGSYNC_HOME`, `CLAUDE_CLI_PATH` и `TGSYNC_LOG` для лога в файл.
- Dockerfile и compose-файл для запуска ноды в контейнере.
- CI на Linux, macOS и Windows; архивы GoReleaser для Linux, macOS и Windows на amd64 и arm64.
- Повтор запросов к Telegram при ограничении частоты и сбоях сети.

### Безопасность
- Управлять нодой могут только пользователи из `ALLOWED_USER_IDS` и только в её группе и темах.
- Служебные файлы tgsync (`.env`, база и её WAL-файлы) недоступны файловым инструментам, поиску и командам shell с буквальным путём и никогда не отправляются в Telegram.
- Команды shell, которые могут обратиться к папке tgsync в любом написании (`~`, `$HOME`, относительные пути, маски, переменные, вложенные shell, heredoc), требуют кнопки в любом режиме автоодобрения, без «Всегда»; сохранённые правила на них не действуют.
- Запись в файлы, из которых git, Claude Code или shell запускают команды (`.git/`, `.gitattributes`, `.gitmodules`, `.claude/`, `.envrc`, `.mcp.json`, `.vscode/tasks.json`), требует одобрения даже внутри проекта в режиме по запросу; симлинки раскрываются до решения.
- Правила «Всегда» не шире одобренного: команда с первым аргументом, без цепочек; для shell, интерпретаторов, разрушительных команд, обёрток, `ssh`, `sudo` и `git -c` правило не создаётся; правило для файлов действует на одну папку. Старые, более широкие правила больше не действуют.
- Токены sudo одноразовые, привязаны к одобренным вызовам и живут недолго; askpass-сокет отвечает только процессу, чей родитель — настоящий `sudo` с правами root (Linux и macOS); sudo внутри обёрток отклоняется; запрос пароля снимается в конце хода; на Windows sudo выключен.
- Токен бота и пароль sudo убираются из окружения агента; пароль sudo не пишется в логи и базу.
- Проверка «файл внутри папки» учитывает ОС (написания путей Windows и Git Bash, регистр, точки в конце, потоки, жёсткие ссылки); отправляемые файлы читаются через один проверенный дескриптор.
- Паники в обработчиках обновлений перехватываются; скачивание файлов, распознавание речи и чтение истории ограничены по времени или объёму; данные кнопок укладываются в лимиты Telegram; число хранимых кнопок на сессию ограничено; двойное нажатие не создаёт дубликатов сессий и тем.
