# Справочник по настройке

Нода настраивается двумя файлами в **папке ноды**:

| Файл | Обязателен | Зачем |
|---|---|---|
| `.env` | да | токен бота, группа, список доступа, лимиты, дополнительные функции |
| `profiles.yaml` | нет | именованные наборы настроек Claude Code для сессий |

Оба файла читаются один раз при старте. **После любой правки перезапусти ноду.**

Шаблон со всеми переменными и комментариями — [`.env.example`](../../.env.example), пример профилей — [`profiles.example.yaml`](../../profiles.example.yaml).

## Папка ноды

В папке ноды лежат `.env`, `profiles.yaml`, база `data/tgsync.db` и, если включён sudo, сокет `askpass.sock`. При старте tgsync переходит в эту папку, поэтому относительные пути вроде `DB_PATH=./data/tgsync.db` считаются от неё.

Папка выбирается так (побеждает первое совпадение):

1. `TGSYNC_HOME`, если задана (папка должна существовать).
2. Текущая папка, если в ней есть `.env`.
3. `~/.config/tgsync`, если в ней есть `.env`.
4. Системная папка настроек + `tgsync`, если в ней есть `.env`: `%APPDATA%\tgsync` на Windows, `~/Library/Application Support/tgsync` на macOS.
5. Иначе — текущая папка.

Где всё лежит после установки скриптами:

| ОС | Папка ноды | Бинарник | Логи |
|---|---|---|---|
| Linux | `~/.config/tgsync` | `~/.local/bin/tgsync` | journald (`journalctl --user -u tgsync`) |
| macOS | `~/Library/Application Support/tgsync` | `~/.local/bin/tgsync` | `~/Library/Logs/tgsync.log` |
| Windows | `%APPDATA%\tgsync` | `%LOCALAPPDATA%\tgsync\bin\tgsync.exe` | `%APPDATA%\tgsync\tgsync.log` |
| Docker | `~/.config/tgsync` на хосте, в контейнере `/config` | внутри образа | `docker compose logs` |

Первая строка вывода `tgsync check` показывает, какую папку нода взяла.

## Переменные окружения процесса

Эти переменные читаются из настоящего окружения процесса, **не** из `.env`: они нужны раньше, чем найден `.env`.

| Переменная | Что делает |
|---|---|
| `TGSYNC_HOME` | Жёстко задаёт папку ноды. Её ставят задача Windows и Docker-образ. |
| `TGSYNC_LOG` | Дописывать логи в этот файл вместо stderr. Её ставит задача Windows: там нет консоли. |
| `CLAUDE_CONFIG_DIR` | Где Claude Code хранит настройки и историю (по умолчанию `~/.claude`). Отсюда `/history` читает прошлые сессии. |

Служебные, их не трогай: `TGSYNC_ASKPASS`, `TGSYNC_ASKPASS_SOCK`, `TGSYNC_SUDO_TOKEN`.

Процесс `claude` и все инструменты, которые он запускает, наследуют окружение ноды — включая любые дополнительные переменные из `.env`. `TELEGRAM_BOT_TOKEN` и `SUDO_PASSWORD` нода удаляет из своего окружения до запуска сессий, агент их не видит.

## Переменные .env

Формат: одна строка `ИМЯ=значение`, `#` — комментарий, пробелы по краям отбрасываются. `tgsync check` показывает все ошибки конфига сразу.

### Обязательные

| Переменная | Формат | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `123456:ABC-…` | Токен бота этой ноды от @BotFather. Одна нода — один бот: два процесса с одним токеном получают `409 Conflict`. |
| `ALLOWED_USER_IDS` | `123456789` или `123456789,987654321` | Telegram user_id тех, кто управляет нодой. Положительные числа через запятую. Остальным нода молча не отвечает. |
| `GROUP_CHAT_ID` | `-1001234567890` | Id супергруппы с темами. Отрицательный. Одна группа на все ноды. |
| `PROJECTS_ROOT` | абсолютный путь | Папка с проектами. Каждая вложенная папка первого уровня — проект в `/projects` и `/new`. Путь абсолютный, папка доступна на запись (`/newproject` создаёт в ней папки). |

### Нода

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_LANGUAGE` | `en` | Язык интерфейса: `en` или `ru`. Касается сообщений, кнопок, меню команд и `tgsync check`. После смены перезапусти ноду и выполни `tgsync profile`, чтобы обновить описания бота. |
| `NODE_NAME` | hostname | Имя в названии темы управления (`🖥 <имя>`). На каждой машине своё. |
| `DB_PATH` | `./data/tgsync.db` | База SQLite, путь от папки ноды. Папка создаётся с правами `0700`. База в режиме WAL, рядом появляются файлы `-wal` и `-shm`. |
| `CLAUDE_CLI_PATH` | пусто (ищется в `PATH`) | Полный путь к `claude`, если в `PATH` сервиса его нет. На Windows подходит только нативный `claude.exe`; обёртка npm `claude.cmd` не запускается. |

### Лимиты и таймеры

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MAX_PARALLEL_SESSIONS` | `3` | Сколько ходов агента идёт одновременно. Открытых сессий может быть больше, лишние ходы ждут в очереди. Целое больше нуля. |
| `IDLE_TIMEOUT` | `2h` | Через сколько гасить простаивающий процесс `claude`, чтобы освободить память. Следующее сообщение продолжит ту же сессию. `0` — не гасить. |
| `STALL_WARN` | `20m` | Предупредить в теме, если ход молчит дольше (время ожидания твоего ответа не считается). `0` — выкл. |
| `REMIND_EVERY` | `2h` | Напоминать о неотвеченном запросе разрешения или вопросе. `0` — выкл. |
| `MAX_TURN_DURATION` | `0` | Прервать ход, который идёт дольше. `0` — без лимита. |

### Сессии

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AUTO_SEND_GLOBS` | пусто | Маски через запятую. Файлы, изменённые за ход и подходящие под маску, приходят в тему в конце хода. `**/` в начале — «в любой папке» (`**/*.md` ловит и `README.md`, и `docs/a.md`); остальные маски сравниваются с путём от корня проекта (`reports/*.pdf`). Документы, на которые агент сослался в ответе, приходят и без маски. Не больше 5 файлов за ход, остальные доступны кнопками. |
| `DEFAULT_PROFILE` | `full` | Профиль, если ни `/new … --profile`, ни `projects.<имя>.profile` в `profiles.yaml` его не задали. Должен существовать, `tgsync check` это проверяет. |
| `SHOW_HOOK_OUTPUT` | `true` | Показывать в теме сообщения hooks для пользователя (`systemMessage`) и сбои hooks. Значения: `true/false`, `1/0`, `yes/no`. |

### sudo

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SUDO_MODE` | `off` | `off`, `env` или `telegram`, см. [sudo](#sudo). На Windows всегда `off`. |
| `SUDO_PASSWORD` | пусто | Пароль для `SUDO_MODE=env`, в этом режиме обязателен. Пробелы не обрезаются. |

### Голосовые

| Переменная | По умолчанию | Описание |
|---|---|---|
| `STT_URL` | пусто (голосовые выкл.) | Адрес своего сервера распознавания с API как у OpenAI, например `http://127.0.0.1:8000`. Только `http` или `https`. Нода шлёт `POST {STT_URL}/v1/audio/transcriptions`. |
| `STT_MODEL` | `Systran/faster-whisper-small` | Имя модели для сервера. |
| `STT_TIMEOUT` | `60s` | Лимит на скачивание и распознавание одного сообщения. `0` снимает этот лимит, но HTTP-запрос всё равно обрывается через 2 минуты. |
| `STT_MAX_SECONDS` | `300` | Самое длинное голосовое в секундах. На более длинные бот отвечает отказом. |

## Длительности

`IDLE_TIMEOUT`, `STALL_WARN`, `REMIND_EVERY`, `MAX_TURN_DURATION` и `STT_TIMEOUT` пишутся в формате Go: число и единица `s`, `m` или `h`, можно сочетать: `45s`, `30m`, `2h`, `1h30m`. Просто `0` выключает таймер. Число без единицы (кроме `0`) и отрицательное значение — ошибка.

## sudo

У Bash агента нет терминала, поэтому `sudo` не может спросить пароль сам. tgsync даёт ему askpass-мост (только Linux и macOS):

1. Агент хочет выполнить команду с `sudo` — в теме появляется запрос `🔐 sudo` с кнопками ✅/❌. Кнопки «Всегда» для sudo нет.
2. После ✅ каждый настоящий вызов `sudo` в команде (его находит shell-парсер) получает одноразовый токен на 5 минут и до конца хода.
3. `sudo` запускает `tgsync` как `SUDO_ASKPASS`, тот спрашивает ноду через unix-сокет `askpass.sock` (права `0600`). Нода отвечает только на действующий токен и только процессу, который запустил настоящий setuid-`sudo`.

| Режим | Откуда пароль | Чем платишь |
|---|---|---|
| `off` | ниоткуда: команды с sudo отклоняются | Самый безопасный. Оставь его, если sudo не нужен. |
| `env` | `SUDO_PASSWORD` в `.env` | Пароль лежит на диске открытым текстом (держи `.env` с правами `0600`). Агент работает под твоим пользователем и технически может прочитать файл; tgsync запрещает это правилами, а не правами ОС. |
| `telegram` | вводишь в теме после ✅, бот сразу удаляет сообщение | Пароль идёт через серверы Telegram (Bot API не шифрует end-to-end) и виден участникам группы до удаления. Нужно право бота «Удаление сообщений», без него `tgsync check` выдаст ошибку. Пароль спрашивается на каждую команду, до 3 попыток на вызов. Неверный пароль — неудачный вход, `pam_faillock` может заблокировать учётку. |

Надёжнее любого режима — правило `NOPASSWD` в `/etc/sudoers.d/` только для нужных команд:

```
user ALL=(root) NOPASSWD: /usr/bin/systemctl restart myapp
```

Не задавай `SUDO_PASSWORD` через `Environment=` в systemd или `environment:` в compose: оттуда он виден в `/proc/<pid>/environ`. Держи его только в `.env` — нода читает файл и убирает пароль из своего окружения.

Режим автоодобрения (🟢 всё сам / 🟡 всё, кроме sudo / 🔴 по запросу) задаётся не в `.env`, а в Telegram командой `/approve`, и хранится в базе. По умолчанию — 🔴 по запросу.

## Голосовые сообщения

1. Подними свой сервер распознавания (CPU-образ [speaches](https://github.com/speaches-ai/speaches)):
   ```bash
   docker compose -f deploy/stt/compose.yaml up -d
   ```
   Он слушает только `127.0.0.1:8000`.
2. Один раз скачай модель (~480 МБ, остаётся в volume Docker):
   ```bash
   curl -X POST http://127.0.0.1:8000/v1/models/Systran/faster-whisper-small
   ```
3. В `.env`:
   ```
   STT_URL=http://127.0.0.1:8000
   ```
4. Перезапусти ноду.

Модель `small` на CPU распознаёт минуту речи за 10–20 секунд. На машине с GPU подними тот же сервер с образом `latest-cuda` и моделью побольше, затем поменяй `STT_URL` и `STT_MODEL`. Звук не уходит в облачные сервисы; если сервер распознавания стоит на другой машине, ходи к нему через VPN или TLS.

Распознаются голосовые и аудиофайлы (до 20 МБ — лимит Telegram на скачивание ботом), агенту уходит текст.

## profiles.yaml

`profiles.yaml` лежит рядом с `.env`. Без него есть только встроенный профиль `full`.

```yaml
profiles:
  <имя>:
    setting_sources: [user, project, local]   # необязательно
    env:                                       # необязательно
      NAME: "value"
    settings:                                  # необязательно
      <любые ключи settings.json Claude Code>
projects:
  <папка проекта>:
    profile: <имя>
```

| Ключ | Тип | Смысл |
|---|---|---|
| `profiles.<имя>.setting_sources` | список из `user`, `project`, `local` | Какие файлы настроек Claude Code читать: `user` — `~/.claude/settings.json` (и плагины пользователя), `project` — `.claude/settings.json`, `local` — `.claude/settings.local.json`. Не задано или пусто — все три. |
| `profiles.<имя>.env` | словарь строк | Дополнительные переменные окружения процесса `claude` этой сессии. Значения вроде `"off"` или `"1"` бери в кавычки, чтобы YAML оставил их строками. |
| `profiles.<имя>.settings` | словарь | Настройки поверх остальных, передаются как `claude --settings '<json>'`. Подходит любой ключ `settings.json`: `enabledPlugins`, `permissions`, `model` и т. д. |
| `projects.<папка>.profile` | строка | Профиль проекта по умолчанию (имя папки в `PROJECTS_ROOT`). |

Порядок выбора для новой сессии:

1. `/new <проект> <задача> --profile <имя>`
2. `projects.<проект>.profile`
3. `DEFAULT_PROFILE` из `.env` (по умолчанию `full`)

`full` есть всегда: «всё из `~/.claude`, как в терминале». Свой `full` в файле его переопределяет. Неизвестное имя профиля — ошибка; `/profiles` в Telegram показывает, что загружено.

## Примеры

Минимальный `.env`:

```
TELEGRAM_BOT_TOKEN=123456:ABC-replace-with-your-token
ALLOWED_USER_IDS=123456789
GROUP_CHAT_ID=-1001234567890
PROJECTS_ROOT=/home/user/projects
```

Вторая нода в той же группе (другая машина):

```
TELEGRAM_BOT_TOKEN=654321:XYZ-token-of-the-second-bot
ALLOWED_USER_IDS=123456789
GROUP_CHAT_ID=-1001234567890
PROJECTS_ROOT=/home/user/code
NODE_NAME=desktop
```

Нагруженный сервер сборки с голосом и строгими лимитами:

```
MAX_PARALLEL_SESSIONS=6
IDLE_TIMEOUT=30m
STALL_WARN=10m
MAX_TURN_DURATION=3h
AUTO_SEND_GLOBS=**/*.md,**/*.pdf,reports/*.html
STT_URL=http://127.0.0.1:8000
```

`profiles.yaml`: выключить один плагин в сессиях из Telegram, а песочницу держать только на настройках проекта:

```yaml
profiles:
  quiet:
    settings:
      enabledPlugins:
        "example-plugin@example-marketplace": false
  project-only:
    setting_sources: [project, local]
projects:
  sandbox:
    profile: project-only
```
