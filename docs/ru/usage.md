## Устройство группы

Каждая машина с tgsync — **нода** со своим ботом. Все ноды работают в одной Telegram-группе с включёнными темами:

- у каждой ноды есть тема управления `🖥 <имя ноды>`;
- у каждой сессии агента — своя тема `проект · задача`.

Нода реагирует только на пользователей из `ALLOWED_USER_IDS` и только в своих темах. Чужие темы (других нод) она не трогает.

Цвет иконки темы один на ноду, поэтому темы разных компьютеров легко отличить. Иконка показывает состояние сессии: 💻 — открыта, ❌ — упала (напиши сообщение, чтобы продолжить), ✅ — закрыта.

## Тема ноды

### Меню

Напиши `/menu` или любой текст — бот покажет меню:

| Кнопка | Что делает |
|---|---|
| **📁 Проекты** | список проектов; проект → **▶ Новая сессия** или **🕘 История** |
| **🕘 История** | последние сессии Claude Code по всем проектам (см. [История](#история-продолжить-сессию-из-терминала)) |
| **🧵 Сессии** | открытые сессии со ссылками на темы |
| **➕ Новый проект** | бот спросит имя; ответь сообщением (латиница, цифры, `.`, `_`, `-`), `/cancel` — отмена |
| **🔐 Автоодобрение** | режим одобрения команд для всей ноды (см. [Разрешения](#разрешения)) |
| **❓ Справка** | краткая справка |

### Команды

| Команда | Что делает |
|---|---|
| `/menu` | меню кнопками |
| `/projects` | список проектов; кнопка открывает проект |
| `/newproject имя` | создать папку проекта в `PROJECTS_ROOT` и выполнить `git init`; без имени бот спросит его |
| `/new проект задача` | новая сессия в отдельной теме; агент сразу берётся за задачу |
| `/new проект` | новая сессия; задачу напишешь первым сообщением в её теме |
| `/new проект --profile имя задача` | новая сессия с профилем из `profiles.yaml` |
| `/profiles` | список профилей |
| `/sessions` | открытые сессии со ссылками |
| `/history` | последние 10 сессий Claude Code по всем проектам |
| `/history проект` | то же для одного проекта |
| `/usage` | лимиты подписки (процент, время сброса) и расход токенов за сегодня и за 7 дней по проектам |
| `/approve` | режим автоодобрения |
| `/cancel` | отменить ввод имени проекта |
| `/help` | справка |

Тему управления удалили? Напиши `/control` в общей теме (General): каждая нода пересоздаст свою тему, если её нет, и ответит ссылкой. Нода также сама заметит пропажу темы в течение минуты и создаст её заново.

### Закреплённая карточка

В теме ноды закреплена карточка: имя ноды, число открытых и закрытых сессий, время запуска («🟢 онлайн с …»). Под ней две кнопки:

- **🧹 Уборка** — показывает темы, которые можно удалить: закрытые сессии и упавшие без единого ответа агента. Удаляет только после **🗑 Удалить**; **Отмена** ничего не трогает. Вместе с темой пропадает её история.
- **🧽 Очистить тему** — сразу удаляет служебные сообщения в теме ноды (ответы бота и твои команды).

### Порядок в теме ноды

- Сообщения в теме ноды (твои команды и ответы бота) удаляются сами примерно через час. Карточка и уведомление о правах остаются.
- Новое меню с кнопками заменяет предыдущее: в теме всегда одно актуальное меню.
- Тему General бот скрывает один раз; если ты откроешь её снова, она останется видимой. Аватар и описание группы бот ставит один раз и только если их нет.
- Если боту не хватает необязательных прав администратора, он один раз напишет, чего именно не хватает и что без этого не работает.

## Тема сессии

Сессия — это один разговор с Claude Code в папке проекта. Всё, что ты пишешь в её теме, получает агент.

| Действие | Результат |
|---|---|
| обычный текст | сообщение агенту. Если ход уже идёт, сообщение встаёт в очередь (см. ниже) |
| документ, фото, скриншот | сохраняется в проект и передаётся агенту (см. [Файлы](#файлы)) |
| голосовое 🎙 | распознаётся своим STT-сервером (см. [Голосовые](#голосовые)) |
| `/stop` | прервать текущий ход; сессия остаётся |
| `/mode default` | обычный режим Claude Code: опасные действия спрашивают разрешение |
| `/mode acceptEdits` | правки файлов без вопросов |
| `/mode plan` | только планирование, без изменений |
| `/ls [папка]` | файлы проекта кнопками: 📁 открыть папку, 📄 прислать файл, ⬆ .. наверх, ➡ ещё |
| `/file путь` | прислать файл проекта, например `/file docs/plan.md` |
| `/skills` | команды и skills, доступные агенту (плагины, `/code-review` и т. п.) |
| `/agents` | панель субагентов заново внизу чата |
| `/context` | заполненность контекста и кнопка **🗜 Сжать** |
| `/usage` | расход этой сессии: ходы, токены, оценка стоимости |
| `/close` | завершить сессию и закрыть тему |
| `/help` | справка по сессии |
| `/любая-другая` | уходит агенту как есть (команды плагинов, например `/code-review`) |

### Очередь

Пока агент работает, новые сообщения встают в очередь и уйдут следующим ходом. На сообщении, которое ждёт или обрабатывается, стоит реакция 👀. Под уведомлением «📥 В очереди» есть кнопка **⚡ Отправить сейчас**: она прерывает текущий ход и отправляет это сообщение первым.

Ходы разных сессий идут параллельно, но не больше `MAX_PARALLEL_SESSIONS` на ноде и не больше одного на проект. Сессия, которой не хватило места, ждёт в состоянии ⏳.

### Остановить и закрыть

- **⏹ Остановить** под статусом хода или `/stop` прерывает ход. Сессия и контекст остаются.
- `/close` или **✖ Закрыть** (с подтверждением **Да, закрыть** / **Отмена**) останавливает процесс и закрывает тему. Закрытую сессию можно продолжить позже через `/history`.
- Можно просто удалить тему в Telegram: нода остановит агента и закроет сессию сама — активную сразу, ожидающую в течение ~10 минут.
- Сессия, закрытая без единого ответа агента, удаляется вместе с темой.

### Кнопки под ответом

Под ответом агента одна кнопка **⋯**. Она раскрывает панель:

- **📂 Файлы** — то же, что `/ls`;
- **⚙ Режим** — выбор режима Claude Code (`default`, `acceptEdits`, `plan`) с пояснениями;
- **✖ Закрыть** — закрыть сессию с подтверждением.

## Ход работы

**Статус-сообщение** обновляется примерно каждые 3 секунды: время, номер шага, текущее действие, действие субагента и 💬 последняя реплика агента между шагами. Под ним кнопка **⏹ Остановить**. В конце хода статус удаляется.

Состояние сессии показано значком в статусе и в `/sessions`:

| Значок | Значение |
|---|---|
| 🔄 | запускается процесс `claude` |
| ▶ | агент работает |
| ❓ | агент ждёт твоего ответа или разрешения |
| 💤 | ход закончен, можно писать дальше |
| ⏳ | в очереди: занят лимит параллельных сессий или проект |
| ⏸ | нода перезапускалась во время хода |
| ❌ | ошибка; следующее сообщение продолжит сессию |
| ✅ | сессия закрыта |

**Ответ агента** — его последнее сообщение за ход, одним сообщением со звуком. Внизу курсивом итог: длительность, число шагов, стоимость и `🧠 N%` заполненности контекста.

**Долгие ходы.** Лимита по времени по умолчанию нет (`MAX_TURN_DURATION=0`). Если ход молчит дольше `STALL_WARN` (20 минут), придёт предупреждение с кнопками **⏳ Ждать** и **⏹ Остановить**. Неотвеченный запрос разрешения или вопрос бот напомнит через `REMIND_EVERY` (2 часа). Процесс `claude` в простое гасится через `IDLE_TIMEOUT` (2 часа); следующее сообщение продолжит сессию с тем же контекстом.

**Плагины и hooks.** Плагины, skills и hooks из `~/.claude` работают как в терминале. Если MCP-серверу нужна авторизация, в теме появится сообщение с 🔌 — авторизуй его в интерактивном `claude`. Сообщения hooks, адресованные человеку, и сбои hooks приходят серым курсивом с 🪝. Выключить: `SHOW_HOOK_OUTPUT=false`.

## Итог хода: diff, коммит, откат

Если агент менял файлы, после ответа приходит сообщение «📎 Изменено за ход: N · +добавлено −удалено» со списком файлов (до 10) и изменениями по каждому: `+3 −1`, `(новый)`, `(удалён)`, `(бинарный)`. ✓ отмечает файлы, которые уже присланы в тему.

В git-проекте tgsync перед каждым ходом и после него снимает снимок рабочего дерева (через временный индекс: твой индекс, ветки и stash не меняются). Поэтому под итогом есть кнопки:

- **🔀 Diff** — присылает файлом `turn-N.diff` все изменения этого хода.
- **✅ Коммит** — отправляет агенту задачу закоммитить изменения этого хода в стиле репозитория. Если в тех же файлах есть более ранние незакоммиченные правки, агент спросит, коммитить ли их.
- **↩ Откатить** — после подтверждения (**Да, откатить** / **Нет**) возвращает файлы к состоянию до хода; новые файлы удаляются. Файлы, изменённые уже после хода, не трогаются; бот перечислит, что пропущено. Агент узнает об откате со следующим сообщением.

Коммит и откат работают только для последнего хода и только когда агент не занят. Кнопки хранятся для последних 5 ходов сессии. Вне git список файлов приходит без кнопок.

## Файлы

### От агента к тебе

- Агент отправляет документы для тебя (spec, план, отчёт) инструментом `send_file`; ему об этом сказано в системном промпте.
- Если агент упомянул путь к документу, который создал или изменил в этой сессии, бот пришлёт его сам.
- Файлы, подходящие под `AUTO_SEND_GLOBS` (например `**/*.md`), приходят в конце каждого хода.
- `/file путь` и `/ls` присылают любой файл проекта по запросу.

Без запроса за ход приходит не больше 5 файлов, одна и та же версия файла не присылается дважды. Отправляются только файлы внутри папки проекта размером до 50 МБ; служебные файлы tgsync не отправляются никогда.

### От тебя к агенту

Отправь в тему сессии документ, фото или скриншот:

- **с подписью** — агент сразу получает путь к файлу и подпись как задачу;
- **без подписи** — бот ответит «📎 Получен», и файл уйдёт агенту вместе с твоим следующим сообщением. Можно прислать несколько файлов, а потом написать задачу.

Файлы сохраняются в `.tgsync/inbox/` внутри проекта. Эта папка сама добавляется в `.git/info/exclude` и в коммиты не попадает. Telegram разрешает ботам скачивать файлы до 20 МБ.

## Голосовые

Голосовые работают, если задан `STT_URL` — адрес своего сервера распознавания речи (готовый `deploy/stt/compose.yaml`, см. [установку](setup.md)). Облачные сервисы не используются.

1. Отправь голосовое в тему сессии. Бот покажет «🎙 Распознаю…», затем расшифровку.
2. Агент получает расшифровку с пометкой, что распознавание могло ошибиться, пересказывает, как понял задачу, и ждёт подтверждения.
3. Ответь «да» (текстом или голосом) или поправь.

Если агент ждёт ответ на вопрос (**✍ Свой ответ**), голосовое станет этим ответом. Максимальная длина — `STT_MAX_SECONDS` (300 с).

## Разрешения

### Что разрешено без вопросов

В режиме **🔴 По запросу**:

- чтение файлов и поиск;
- правка файлов внутри папки проекта, кроме файлов, из которых git, Claude Code или shell запускают команды (`.git/`, `.gitattributes`, `.gitmodules`, `.claude/`, `.envrc`, `.mcp.json`, `.vscode/tasks.json`);
- то, что ты раньше разрешил кнопкой «Всегда»;
- то, что разрешено в настройках Claude Code (`~/.claude/settings.json`, настройки проекта).

Остальное приходит сообщением «🔐 Запрос разрешения» с командой, её описанием и кнопками:

- **✅ Разрешить** — один раз;
- **❌ Отклонить** — агент получит отказ; причину можно написать следующим сообщением;
- **♾ Всегда: …** — запомнить для этого проекта.

### Что запоминает «Всегда»

- Для команд shell — команду с первым аргументом, например `go test` или `ls -la`. Цепочки (`&&`, `;`, `|`, подстановки, перенаправления) под правило не подходят.
- Для shell и интерпретаторов (`bash`, `python3`, `node` …), разрушительных команд (`rm`, `dd`, `chmod`, `find` …), обёрток (`env`, `xargs`, `eval`, `timeout` …), `ssh`, `sudo` и `git` с глобальными опциями (`git -c …`) кнопки «Всегда» нет — только разовое разрешение.
- Для правки файла вне проекта — папку этого файла (без подпапок).
- Правило вида `npm run` разрешает любой скрипт из `package.json`, поэтому выбирай «Всегда» для узких команд.

### Автоодобрение

`/approve` или **🔐 Автоодобрение** в меню задаёт режим для всей ноды:

| Режим | Что происходит |
|---|---|
| **🟢 Всё сам** | любые команды без вопросов, включая sudo (если sudo включён) |
| **🟡 Всё, кроме sudo** | всё без вопросов, на sudo приходит кнопка |
| **🔴 По запросу** (по умолчанию) | кнопка на каждое действие, которое не разрешено правилами выше |

В режимах 🟢 и 🟡 строка статуса показывает, что делает агент («▶ Прогоняю тесты»), а не саму команду. Деструктивные команды (удаление файлов, `git push`, `git reset`, остановка процессов, sudo, …) по-прежнему оставляют тихую заметку «✅ авто: …» с командой. В любом режиме кнопкой приходят вопросы агента и команды, которые могут обращаться к папке tgsync (`.env`, база). Подробнее о рисках — в [security.md](security.md).

`/mode` в теме сессии — другое: это режим самого Claude Code (`default`, `acceptEdits`, `plan`) для одной сессии.

## Вопросы агента

Когда агент задаёт вопрос (AskUserQuestion), он приходит с кнопками:

- нажми вариант;
- при мультивыборе отметь галочками и нажми **Готово**;
- **✍ Свой ответ** — следующее твоё сообщение (или голосовое) станет ответом. Команды `/stop`, `/close`, `/mode` при этом всё равно работают как команды.

Если вопросов несколько, они идут по очереди («Вопрос 1 из 3»).

## sudo

Работа с `sudo` зависит от `SUDO_MODE` на ноде (см. [security.md](security.md#sudo)):

- `off` (по умолчанию, и всегда на Windows) — команды с sudo отклоняются, агент попросит выполнить их вручную;
- `env` — пароль берётся из `SUDO_PASSWORD` в `.env`;
- `telegram` — пароль спрашивается в теме.

Каждая команда с sudo приходит отдельным запросом «🔐 sudo — команда выполнится с правами root» только с кнопками ✅/❌: «Всегда» для sudo не бывает (в режиме автоодобрения 🟢 кнопки нет).

В режиме `telegram` после ✅ бот напишет «🔑 Нужен пароль sudo». Отправь пароль следующим сообщением — бот сразу удалит его из чата («🔑 Пароль получен, сообщение удалено»). Несколько вызовов sudo в одной одобренной команде получают один ответ. Если пароль неверный, sudo спросит снова — до 3 попыток. Если ход закончился, запрос пароля снимается.

## Контекст, расход и лимиты

- **Контекст.** В итоге хода — `🧠 N%`. Около 70% (или раньше, если авто-сжатие настроено раньше) придёт подсказка «💡 Контекст N%» с кнопкой **🗜 Сжать**: она отправит агенту `/compact`. Когда история сжата, в теме появится «🗜 История сжата». `/context` показывает подробности.
- **Расход.** `/usage` в теме сессии — ходы, токены и оценка стоимости этой сессии. `/usage` в теме ноды — лимиты подписки и расход за сегодня и за 7 дней по проектам.
- **Лимиты подписки.** Когда окно подписки (5 часов, 7 дней…) подходит к пределу, в тему сессии и в тему ноды приходит ⚠️ с процентом и временем сброса; когда лимит исчерпан — ⛔ со звуком; когда снова доступен — ✅ в теме ноды. Каждое предупреждение приходит один раз на окно.

## Субагенты

Когда агент запускает субагентов, в теме появляется **панель агентов**: какой агент, над чем работает и кто его вызвал (вложенные — под вызвавшим, со сдвигом ↳). В списке до 12 агентов, остальные свёрнуты.

Кнопка агента открывает его карточку в том же сообщении: время, инструменты, что делает сейчас или итог. Кнопки: **⏹ Остановить**, **📄 Результат** (полный ответ файлом), **⬅ Назад**.

`/agents` присылает панель заново внизу чата. Фоновые агенты работают и после конца хода; их результат агент разбирает в ходе-продолжении («🤖 продолжение после агента …»), который не занимает слот `MAX_PARALLEL_SESSIONS`. `/stop` не останавливает фоновых агентов — бот напомнит, что их можно остановить в панели. `/close` останавливает всех.

## История: продолжить сессию из терминала

`/history` показывает последние сессии Claude Code по проектам в `PROJECTS_ROOT`, включая начатые в терминале и в приложении. Значок — источник: 🖥 приложение, ⌨ терминал, 🤖 бот. Под каждой строкой — последний запрос.

Нажми номер сессии — появится тема «🔗 Подключено к сессии …» с последним запросом. Следующее сообщение продолжит сессию с полным контекстом.

- Если сессия **🟢 активна** (менялась в последние 2 минуты), в Telegram продолжится её **копия** (fork): исходная сессия не изменится, и два процесса не будут писать в одну историю.
- Если сессия уже открыта в Telegram, бот пришлёт ссылку на её тему вместо второй темы.
- Кнопки старых списков со временем устаревают — тогда повтори `/history`.

## Профили

Профиль задаёт, с какими настройками, плагинами и hooks запускается `claude` в сессиях бота. Профиль `full` есть всегда: всё из `~/.claude`, как в терминале.

Профили описываются в `profiles.yaml` рядом с `.env` (пример — `profiles.example.yaml`): источники настроек, переменные окружения процесса, поверх-настройки (например, выключить плагин). Профиль выбирается так: `/new проект --profile имя`, иначе `projects.<проект>.profile` из `profiles.yaml`, иначе `DEFAULT_PROFILE`. В начале сессии бот пишет «🧩 профиль …». Подробнее — в [configuration.md](configuration.md).

## Несколько нод

На каждой машине своя нода со своим ботом и своей темой `🖥 <имя>`, все в одной группе. `GROUP_CHAT_ID` одинаковый у всех нод, `NODE_NAME` — разный. Каждая нода отвечает только в своих темах; команды пиши в тему нужной ноды. `/control` в общей теме получают все ноды — каждая ответит ссылкой на свою тему. На одной машине запускай одну ноду: вторая с той же папкой откажется стартовать.

## Сценарии

**Новая задача с телефона.** В теме ноды: `/new myapp добавь тесты для auth`. Открой новую тему по ссылке и следи за ходом.

**Долгая задача.** Уйди и вернись позже: итог хода придёт уведомлением. Если агент ждёт разрешения, статус покажет ❓, а бот напомнит.

**Сменить курс.** `/stop`, потом новое сообщение с уточнением. Или отправь уточнение и нажми **⚡ Отправить сейчас**.

**Проверить и закоммитить.** Под итогом хода: **🔀 Diff** → просмотреть → **✅ Коммит**. Не понравилось — **↩ Откатить**.

**Процесс упал или нода перезапустилась.** Напиши в тему любое сообщение: сессия продолжится с тем же контекстом.

## Ограничения

- Нельзя в реальном времени видеть и направлять сессию, которая *прямо сейчас* идёт в терминале: `/history` продолжает её копией.
- `/history` видит только проекты внутри `PROJECTS_ROOT`.
