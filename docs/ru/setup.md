# Установка и обслуживание

Здесь — путь от нуля до работающей ноды tgsync и повседневное обслуживание. Все переменные описаны в [configuration.md](configuration.md), разбор типовых проблем — в [troubleshooting.md](troubleshooting.md).

**Термины.** *Нода* — машина, на которой работает tgsync со своим Telegram-ботом. Все ноды живут в одной *группе с темами* (супергруппа с включёнными Topics). У каждой ноды есть *тема управления* `🖥 <имя ноды>`, у каждой сессии Claude Code — своя тема.

## 1. Что нужно заранее

| Что | Зачем |
|---|---|
| Linux, macOS или Windows 10/11 (amd64 или arm64) | Поддерживаемые платформы. sudo работает только на Linux и macOS. |
| Claude Code, установленный **и авторизованный** | tgsync управляет CLI `claude`, своего доступа к модели у него нет. |
| Git | Диффы и проекты; на Windows Claude Code ещё нужен Git for Windows (Git Bash). |
| Go 1.27.1 или новее | Только для сборки из исходников (версия из `go.mod`). С архивом релиза не нужен. |
| Аккаунт Telegram | Чтобы создать бота и группу. |

### 1.1 Claude Code

Linux / macOS:

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude            # интерактивная сессия; если попросит — выполни /login
claude --version  # должно работать в той же оболочке, из которой будешь ставить tgsync
```

Windows (PowerShell):

```powershell
irm https://claude.ai/install.ps1 | iex
claude
```

Особенности Windows:

- Ставь **нативным** установщиком. Пакет из npm кладёт обёртку `claude.cmd`, которую tgsync запустить не может (`tgsync check` так и скажет).
- Поставь [Git for Windows](https://git-scm.com/download/win): инструмент Bash у Claude Code работает через Git Bash.

На сервере без экрана войди один раз интерактивно (`claude`, затем `/login`) или выпусти долгоживущий токен командой `claude setup-token` и допиши `CLAUDE_CODE_OAUTH_TOKEN=…` в `.env` tgsync: процесс `claude` наследует окружение ноды.

MCP-серверы со статусом `needs-auth` авторизуй в интерактивном `claude` на этой же машине: в headless-режиме OAuth через браузер не пройти.

### 1.2 Go (только для сборки из исходников)

Установи Go с <https://go.dev/dl/> и проверь:

```bash
go version   # go1.27.1 или новее
```

## 2. Telegram: бот и группа

### 2.1 Бот (у каждой ноды свой)

1. Открой [@BotFather](https://t.me/BotFather) и отправь `/newbot`.
2. Задай имя и username, который кончается на `bot`, например `ExampleNodeBot`.
3. Сохрани токен (`123456:ABC-…`). Это пароль: у кого токен, тот управляет ботом.

Каждой машине нужен **свой** бот. Telegram отдаёт обновления по токену только одному процессу, второй получает `409 Conflict`.

Делать **не нужно**:

- менять privacy mode: бот будет администратором, а администраторы и так получают все сообщения группы;
- задавать команды через `/setcommands`: tgsync сам регистрирует меню команд для группы при каждом старте.

### 2.2 Группа с темами

1. Создай в Telegram новую группу (бота можно добавить сразу или позже).
2. Настройки группы → **Темы** (Topics) → включить. Группа станет супергруппой, и её id в этот момент **поменяется** — поэтому id узнавай только после этого шага.
3. Группа должна быть закрытой: все её участники видят весь вывод агента.

### 2.3 Бот — администратор

Настройки группы → **Администраторы** → **Добавить администратора** → выбери бота. Включи права:

| Право | Обязательно | Что даёт |
|---|---|---|
| **Управление темами** | **да** | Создавать, переименовывать и закрывать темы, скрыть General. Без него нода не запустится. |
| **Закрепление сообщений** | желательно | Закрепить карточку ноды (счётчики и кнопки уборки) в теме управления. |
| **Изменение профиля группы** | желательно | Один раз поставить аватар и описание группы, если их нет. |
| **Удаление сообщений** | желательно | Удалять пустые темы и темы по кнопке 🧹 Уборка (иначе они только закрываются), чистить тему управления; обязательно для `SUDO_MODE=telegram` (введённый пароль удаляется). |

Остальные права не используются. Если какого-то желательного права нет, бот напишет в теме управления, что без него не работает.

### 2.4 Свой user_id

Напиши [@userinfobot](https://t.me/userinfobot) (или похожему боту) и возьми числовой `Id`, например `123456789`. Он пойдёт в `ALLOWED_USER_IDS`.

### 2.5 Id группы

Способ А, Telegram Web: открой группу на <https://web.telegram.org/a/>. Адрес заканчивается на `#-1001234567890` — это число с минусом и есть id.

Способ Б, Bot API (только пока tgsync с этим токеном **не** запущен):

1. Отправь в группу любое сообщение.
2. Выполни, подставив свой токен:
   ```bash
   curl -s "https://api.telegram.org/bot123456:ABC-your-token/getUpdates"
   ```
3. Найди в ответе `"chat":{"id":-100…`.

Id супергруппы всегда начинается с `-100`. Короткий отрицательный id вроде `-123456789` значит, что темы ещё не включены.

### 2.6 Несколько нод в одной группе

Для каждой машины повтори 2.1 и 2.3: новый бот, администратор в **той же** группе с теми же правами. У всех нод одинаковые `GROUP_CHAT_ID` и `ALLOWED_USER_IDS` и разные `NODE_NAME`. Каждая нода отвечает только в своих темах.

## 3. Получить tgsync

### Вариант А: сборка из исходников

```bash
git clone https://github.com/ArthurKrantsevich/tgsync.git
cd tgsync
make build          # получится ./bin/tgsync
./bin/tgsync version
```

На Windows без `make`: `go build -o bin\tgsync.exe .\cmd\tgsync`.

Скрипты установки (шаг 5) сами соберут бинарник, если есть Go, так что этот шаг можно пропустить.

### Вариант Б: архив релиза

Когда релиз опубликован на странице GitHub Releases, в нём лежат архивы для `linux`, `darwin` и `windows` на `amd64` и `arm64` и файл `checksums.txt`. В каждом архиве — бинарник `tgsync`, `scripts/`, `docs/`, `.env.example` и `profiles.example.yaml`.

```bash
sha256sum -c checksums.txt --ignore-missing
mkdir tgsync && tar xzf tgsync_*_linux_amd64.tar.gz -C tgsync && cd tgsync
```

На macOS скачанный бинарник может попасть в карантин Gatekeeper; сними его: `xattr -d com.apple.quarantine tgsync`.

В архиве нет Makefile, поэтому запускай скрипт напрямую: `sh scripts/install.sh` (на Windows — `scripts\install.ps1`). Без `go.mod` рядом скрипт не собирает, а копирует готовый бинарник.

## 4. Настройка

Скрипты установки ищут `.env` в папке репозитория (или распакованного архива) и **переносят** его в папку ноды, чтобы вторая копия токена не осталась в проекте. Можно и сразу создать `.env` в папке ноды (таблица путей — в [configuration.md](configuration.md#папка-ноды)).

1. Скопируй шаблон:
   ```bash
   cp .env.example .env
   chmod 600 .env
   ```
2. Заполни четыре обязательных значения:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-replace-with-your-token
   ALLOWED_USER_IDS=123456789
   GROUP_CHAT_ID=-1001234567890
   PROJECTS_ROOT=/home/user/projects
   ```
   `PROJECTS_ROOT` — абсолютный путь; каждая вложенная папка — проект.
3. По желанию задай `NODE_NAME` (по умолчанию hostname) и просмотри остальное в `.env.example`.
4. Проверь до установки:
   ```bash
   make check          # соберёт ./bin/tgsync и выполнит tgsync check
   ```

Так выглядит успешная проверка:

```
tgsync dev · папка /home/user/tgsync
✓ конфиг — .env прочитан
✓ бот — @ExampleNodeBot
✓ группа с темами — -1001234567890
✓ права бота — администратор, все нужные права
✓ профили — full (по умолчанию full)
✓ sudo — SUDO_MODE=off: команды с sudo отклоняются
✓ claude CLI — /home/user/.local/bin/claude 2.x.x (Claude Code)
✓ PROJECTS_ROOT — /home/user/projects
✓ папка базы — data
Всё в порядке.
```

Каждая строка с `✗` говорит, что исправить; подробнее — в [troubleshooting.md](troubleshooting.md).

## 5. Установка как сервис

Выбери один вариант. Никогда не запускай два экземпляра с одним токеном (сервис и терминал, сервис и Docker).

### 5.1 Linux (пользовательский сервис systemd)

```bash
make install        # то же, что sh scripts/install.sh
```

Что делает скрипт:

1. Отказывается продолжать, если у твоего пользователя уже запущен другой `tgsync` (например, `./bin/tgsync run` в терминале).
2. Собирает `~/.local/bin/tgsync` (или копирует бинарник из архива).
3. Создаёт `~/.config/tgsync` и `~/.config/tgsync/data` с правами `0700`.
4. Переносит `.env` из репозитория в `~/.config/tgsync/.env` (права `0600`), если его там ещё нет. Если `.env` нет нигде, кладёт туда `.env.example` и останавливается: заполни файл и запусти `make install` ещё раз.
5. Переносит и старую базу `./data/tgsync.db` из репозитория, чтобы темы сохранились.
6. Запускает `tgsync check` и останавливается при любой ошибке.
7. Пишет `~/.config/systemd/user/tgsync.service` с **текущим `PATH`**, чтобы сервис находил `claude`, `node` и `python` для hooks так же, как твоя оболочка. Поэтому запускай установку там, где `claude --version` работает.
8. Включает и (пере)запускает сервис.
9. Включает *linger* (`loginctl enable-linger`), чтобы нода работала без входа в систему и после перезагрузки. Если не вышло, включи сам:
   ```bash
   sudo loginctl enable-linger "$USER"
   ```

Получается такой unit:

```ini
[Service]
Type=simple
WorkingDirectory=%h/.config/tgsync
Environment="PATH=…твой PATH…"
ExecStart="/home/user/.local/bin/tgsync" run
Restart=on-failure
RestartSec=5
```

Проверь, что `~/.local/bin` есть в `PATH`, тогда `tgsync check` работает из любой папки.

### 5.2 macOS (агент launchd)

```bash
make install
```

Всё как на Linux, кроме:

- папка ноды — `~/Library/Application Support/tgsync`;
- сервис — агент launchd `~/Library/LaunchAgents/dev.tgsync.plist` (метка `dev.tgsync`), стартует при входе и перезапускается после сбоя;
- логи — `~/Library/Logs/tgsync.log`.

Агент launchd работает, только пока ты залогинен в macOS. Чтобы нода не засыпала, оставайся в системе (блокировка экрана не мешает) и отключи сон для текущего источника питания.

### 5.3 Windows (Планировщик заданий)

Нужны нативный Claude Code (`claude.exe`), Git for Windows и Go (если ставишь не из zip-архива релиза). В PowerShell из папки репозитория или архива:

```powershell
Copy-Item .env.example .env
notepad .env
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Что делает скрипт:

1. Отказывается продолжать, если запущен другой `tgsync`, и останавливает старую задачу.
2. Собирает `%LOCALAPPDATA%\tgsync\bin\tgsync.exe` (или копирует `tgsync.exe` из архива).
3. Переносит `.env` в `%APPDATA%\tgsync\.env`, если его там нет (или кладёт туда `.env.example` и останавливается).
4. Запускает `tgsync check` и останавливается при ошибке.
5. Регистрирует задачу `tgsync` для твоего пользователя: запуск при входе, скрытое окно, перезапуск после сбоя. Права администратора не нужны. Логи — `%APPDATA%\tgsync\tgsync.log`.

Ограничения Windows:

- Нода работает, только пока ты залогинен.
- sudo нет: `SUDO_MODE` всегда `off`.
- Права `0600/0700` не действуют; `.env` защищён только правами профиля пользователя (ты и администраторы).

### 5.4 Docker (compose)

Альтернатива для Linux-хоста. Контейнер работает под твоим пользователем, видит те же пути, что хост, и использует твой `~/.claude` (авторизацию, плагины, историю).

1. Сделай конфиг в папке ноды на хосте: `~/.config/tgsync/.env` (шаг 4). `PROJECTS_ROOT` обязателен: compose монтирует его по тому же пути.
2. Убедись, что `~/.claude.json` существует, иначе Docker создаст на его месте папку:
   ```bash
   test -f ~/.claude.json || touch ~/.claude.json
   ```
3. Из папки репозитория собери и запусти (`UID` в bash не экспортируется, поэтому имена другие):
   ```bash
   TGSYNC_UID=$(id -u) TGSYNC_GID=$(id -g) \
     docker compose --env-file ~/.config/tgsync/.env up -d --build
   ```
4. Проверка и логи:
   ```bash
   TGSYNC_UID=$(id -u) TGSYNC_GID=$(id -g) \
     docker compose --env-file ~/.config/tgsync/.env run --rm tgsync check
   docker compose logs -f
   ```

Что монтируется:

| Хост | Контейнер | Зачем |
|---|---|---|
| `~/.config/tgsync` | `/config` | `.env`, `profiles.yaml`, база |
| `~/.claude` | тот же путь | авторизация Claude Code (`.credentials.json` на Linux), плагины, история |
| `~/.claude.json` | тот же путь | состояние аккаунта Claude Code |
| `$PROJECTS_ROOT` | тот же путь | проекты |

Ограничения:

- **Авторизация Claude Code.** Образ ставит Claude Code через npm и берёт вход с хоста из `~/.claude`. На Linux это работает, если ты залогинен на хосте. На macOS вход хранится в Связке ключей, а не в `~/.claude`, и контейнер его не видит: выпусти токен `claude setup-token` и допиши `CLAUDE_CODE_OAUTH_TOKEN=…` в `.env`.
- **Инструменты.** В образе есть `git`, `node`, `python3`, `curl`. Всё остальное для hooks и проектов добавь при сборке:
  ```bash
  TGSYNC_UID=$(id -u) TGSYNC_GID=$(id -g) \
    docker compose --env-file ~/.config/tgsync/.env build --build-arg EXTRA_PACKAGES="golang make"
  ```
- **sudo в контейнере нет**: оставь `SUDO_MODE=off`. Для задач вроде «поставь пакет в систему» используй вариант с systemd.
- Агенту видны только `PROJECTS_ROOT`, `~/.claude` и папка ноды.
- Не запускай сервис systemd и контейнер одновременно.

### 5.5 Запуск в терминале (без сервиса)

Удобно для первого знакомства и отладки:

```bash
make build
./bin/tgsync run
```

Папка ноды выбирается по правилам из [configuration.md](configuration.md#папка-ноды): текущая, если в ней есть `.env`, иначе `~/.config/tgsync` и т. д. Остановка — Ctrl+C. Не запускай так, пока работает сервис.

Подкоманды:

| Команда | Что делает |
|---|---|
| `tgsync run` (по умолчанию) | Запускает ноду. |
| `tgsync check` | Проверяет конфиг, Telegram, права, `claude`, папки. При любой ошибке — код выхода 1. |
| `tgsync profile` | Ставит боту аватар и описания (см. 6.2). |
| `tgsync version` | Печатает версию. |

## 6. Первый запуск и проверка

### 6.1 Что происходит при первом старте

1. Нода читает `.env`, открывает (или создаёт) базу и применяет миграции.
2. Проверяет, что бот — администратор с правом **«Управление темами»**; если нет, завершается с ошибкой (а сервис будет её перезапускать).
3. Создаёт тему управления `🖥 <NODE_NAME>` (или переименовывает существующую; если ты её удалил — создаёт заново).
4. Скрывает тему **General** — один раз на группу. Если потом покажешь её обратно, она так и останется видимой.
5. Если не хватает желательных прав, пишет об этом в теме управления.
6. Если есть право **«Изменение профиля группы»**, а у группы нет фото или описания, ставит их — тоже один раз.
7. Публикует карточку ноды в теме управления и закрепляет её (нужно **«Закрепление сообщений»**). На карточке — счётчики и кнопки 🧹 Уборка.
8. Регистрирует меню команд (`/menu`, `/new`, `/help` …) для группы.
9. Восстанавливает сессии, открытые до перезапуска.

### 6.2 Аватар и описание бота (по желанию, один раз)

```bash
tgsync profile
```

Ставит боту фото профиля, короткое описание (в профиле) и полное (в пустом чате с ботом). Имя бота меняется в @BotFather.

### 6.3 Проверка

1. `tgsync check` заканчивается строкой `Всё в порядке.`
2. Сервис работает:
   - Linux: `systemctl --user status tgsync`
   - macOS: `launchctl print gui/$(id -u)/dev.tgsync`
   - Windows: `Get-ScheduledTask tgsync`
3. В группе есть тема `🖥 <NODE_NAME>` с закреплённой карточкой.
4. Напиши в этой теме `/menu` — бот пришлёт главное меню.
5. Открой сессию: `/new <проект> поздоровайся`. Появится новая тема, туда пойдёт ответ агента.

Если бот молчит — см. [Бот молчит](troubleshooting.md#бот-молчит).

## 7. Дополнительные функции

Всё это — настройки в `.env`, подробности и значения по умолчанию — в [configuration.md](configuration.md).

- **Голосовые сообщения** через свой сервер распознавания: `deploy/stt/compose.yaml`, `STT_URL`. По шагам — в [configuration.md → Голосовые сообщения](configuration.md#голосовые-сообщения). Облачные сервисы не используются.
- **Профили**: `profiles.yaml` рядом с `.env` переключает плагины, источники настроек и окружение для сессии или проекта. См. [configuration.md → profiles.yaml](configuration.md#profilesyaml).
- **sudo**: `SUDO_MODE=off|env|telegram`. Сначала прочитай про риски в [configuration.md → sudo](configuration.md#sudo). Самое безопасное — `off` и узкое правило `NOPASSWD`.
- **Автоотправка файлов**: `AUTO_SEND_GLOBS=**/*.md,**/*.pdf` присылает подходящие изменённые файлы в конце хода.
- **Лимиты**: `MAX_PARALLEL_SESSIONS` (одновременные ходы), `IDLE_TIMEOUT` (гасить простаивающий `claude`), `MAX_TURN_DURATION` (жёсткий лимит хода), `STALL_WARN` (предупреждение о тишине), `REMIND_EVERY` (напоминания о неотвеченных запросах).
- **Автоодобрение**: выбирается в Telegram командой `/approve` (🟢 всё сам / 🟡 всё, кроме sudo / 🔴 по запросу — по умолчанию). Хранится в базе, а не в `.env`.

После правки `.env` или `profiles.yaml` перезапусти ноду.

## 8. Обслуживание

### 8.1 Логи, состояние, перезапуск

| Действие | Linux | macOS | Windows (PowerShell) |
|---|---|---|---|
| Состояние | `systemctl --user status tgsync` или `make status` | `launchctl print gui/$(id -u)/dev.tgsync` или `make status` | `Get-ScheduledTask tgsync` |
| Логи в реальном времени | `journalctl --user -u tgsync -f` или `make logs` | `tail -f ~/Library/Logs/tgsync.log` или `make logs` | `Get-Content -Wait $env:APPDATA\tgsync\tgsync.log` |
| Последние 100 строк | `journalctl --user -u tgsync -n 100` | `tail -n 100 ~/Library/Logs/tgsync.log` | `Get-Content -Tail 100 $env:APPDATA\tgsync\tgsync.log` |
| Перезапуск | `systemctl --user restart tgsync` | `launchctl kickstart -k gui/$(id -u)/dev.tgsync` | `Stop-ScheduledTask tgsync; Get-Process tgsync -ErrorAction SilentlyContinue \| Stop-Process; Start-ScheduledTask tgsync` |
| Остановка | `systemctl --user stop tgsync` | `launchctl bootout gui/$(id -u)/dev.tgsync` | `Stop-ScheduledTask tgsync; Get-Process tgsync -ErrorAction SilentlyContinue \| Stop-Process` |
| Диагностика | `tgsync check` | `tgsync check` | `& $env:LOCALAPPDATA\tgsync\bin\tgsync.exe check` |

Docker: `docker compose logs -f`, `docker compose restart`, `docker compose down`.

При остановке идущие ходы прерываются, открытые сессии продолжатся после следующего старта.

### 8.2 Обновление

```bash
git pull
make install          # Linux/macOS: сборка, проверка, перезапуск
```

Windows: `git pull`, затем `powershell -ExecutionPolicy Bypass -File scripts\install.ps1`.
Архив релиза: распакуй новую версию и запусти её `scripts/install.sh` (или `install.ps1`).
Docker: `git pull`, затем команда `up -d --build` из 5.4.

Конфиг и база не перезаписываются, миграции базы применяются сами при старте. Новые переменные `.env` смотри в списке изменений; если переменной нет, действует значение по умолчанию.

### 8.3 Резервная копия

Копируй папку ноды:

| Файл | Зачем |
|---|---|
| `.env` | токен и настройки (секрет: храни копию зашифрованной) |
| `profiles.yaml` | профили, если используешь |
| `data/tgsync.db`, `-wal`, `-shm` | связь тем и сессий, правила «Всегда», режим автоодобрения, состояние карточки |

База работает в режиме WAL. Для целостной копии либо останови ноду, либо сделай онлайн-копию средствами SQLite:

```bash
sqlite3 ~/.config/tgsync/data/tgsync.db ".backup '/home/user/tgsync-backup.db'"
```

Сессии продолжаются по истории Claude Code (`~/.claude/projects`), так что `~/.claude` тоже стоит держать в обычном бэкапе домашней папки.

### 8.4 Удаление

```bash
make uninstall        # Linux/macOS
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1   # Windows
```

Удаляются сервис и бинарник. Папка ноды (конфиг и база) остаётся — удали её сам, если нужно. Чтобы убрать ноду и из Telegram: удали её темы в группе, исключи бота из группы и удали бота в @BotFather (`/deletebot`). Для Docker: `docker compose down` и удалить образ.

На Linux можно выключить linger, если он больше ни для чего не нужен: `loginctl disable-linger "$USER"`.

### 8.5 Ещё одна нода

На новой машине:

1. Создай нового бота в @BotFather (2.1).
2. Добавь его в **ту же** группу администратором с теми же правами (2.3).
3. Установи tgsync, возьми `.env` с первой ноды и поменяй `TELEGRAM_BOT_TOKEN`, `NODE_NAME` и при необходимости `PROJECTS_ROOT`.
4. `make install` (или аналог для Windows/Docker).

Появится тема `🖥 <новое имя>`. Ноды друг с другом не общаются, каждая обслуживает свои темы.

### 8.6 Перенос ноды на другую машину

1. Останови старую ноду (`systemctl --user stop tgsync` или `make uninstall`): две ноды с одним токеном мешают друг другу.
2. Скопируй папку ноды (`.env`, `profiles.yaml`, `data/`) в папку ноды на новой машине; у `.env` должны остаться права `0600`.
3. Чтобы продолжить старые сессии, скопируй и `~/.claude` (как минимум `~/.claude/projects`), а проекты положи по тем же абсолютным путям. Иначе просто открывай новые сессии, старые темы останутся как история.
4. Если пути другие, поправь `PROJECTS_ROOT` и `CLAUDE_CLI_PATH`. Оставь прежний `NODE_NAME`, чтобы тема управления не переименовалась.
5. Установи и авторизуй Claude Code, затем `make install`.

С тем же токеном и базой нода подхватит свою тему управления и темы сессий.

## 9. Чек-лист безопасности

- [ ] Токен бота лежит только в `.env` с правами `0600` в папке с правами `0700`. Его нет в git (`.env` в `.gitignore`), в истории shell, в unit-файлах systemd и в compose.
- [ ] Если токен утёк — перевыпусти: @BotFather → `/revoke` → бот, впиши новый в `.env` и перезапусти ноду.
- [ ] В `ALLOWED_USER_IDS` только твой id (и тех, кому доверяешь shell-доступ к этой машине).
- [ ] Группа закрытая, в ней только доверенные люди: они видят код, вывод команд и содержимое файлов.
- [ ] У каждой ноды свой бот; ненужные боты удалены из группы.
- [ ] Автоодобрение — 🔴 по запросу, если ты не готов к тому, что в 🟢/🟡 агент выполняет любые команды от твоего пользователя без вопросов.
- [ ] `SUDO_MODE=off`, если sudo не нужен; лучше узкие правила `NOPASSWD`. `SUDO_PASSWORD` никогда не задаётся через окружение systemd или compose.
- [ ] Сервер распознавания (если есть) слушает `127.0.0.1` или доступен только через VPN/TLS.
- [ ] Резервные копии `.env` зашифрованы.
- [ ] Ты читаешь каждую команду перед ✅, особенно те, что трогают папку tgsync или используют sudo.
- [ ] Трафик Bot API не шифруется end-to-end: код и вывод проходят через серверы Telegram.

Подробнее — в [security.md](security.md).
