# Если что-то не работает

С чего начинать всегда:

1. Выполни `tgsync check` (на Windows: `& $env:LOCALAPPDATA\tgsync\bin\tgsync.exe check`). Каждая строка с `✗` называет сломанный шаг.
2. Посмотри последние строки лога:
   - Linux: `journalctl --user -u tgsync -n 100`
   - macOS: `tail -n 100 ~/Library/Logs/tgsync.log`
   - Windows: `Get-Content -Tail 100 $env:APPDATA\tgsync\tgsync.log`
   - Docker: `docker compose logs --tail 100`

## Ошибки конфига

`tgsync check` пишет `✗ конфиг — …`, а `tgsync run` завершается. Все проблемы перечисляются сразу.

| Сообщение | Причина | Что сделать |
|---|---|---|
| `TELEGRAM_BOT_TOKEN is required` (так же для `ALLOWED_USER_IDS`, `GROUP_CHAT_ID`, `PROJECTS_ROOT`) | Переменная пустая или её нет — **либо `.env` вообще не найден** | Посмотри папку в первой строке `tgsync check` (`папка …`). Положи `.env` туда или задай `TGSYNC_HOME`. См. [папка ноды](configuration.md#папка-ноды). |
| `GROUP_CHAT_ID must be a negative supergroup id like -1001234567890` | Id положительный, с пробелами или буквами, или это id пользователя | Нужен id группы со знаком минус ([setup 2.5](setup.md#25-id-группы)). |
| `ALLOWED_USER_IDS: invalid user id "…"` | Не положительное число (например, `@username`) | Числовые id от @userinfobot через запятую. |
| `PROJECTS_ROOT must be an absolute path` | `~/projects` или относительный путь | Полный путь: `/home/user/projects`. `~` не раскрывается. |
| `MAX_PARALLEL_SESSIONS must be a positive integer` | `0`, отрицательное или текст | `1` или больше. |
| `IDLE_TIMEOUT must be a duration like 30m or 2h, got "…"` — так же для `STALL_WARN`, `REMIND_EVERY`, `MAX_TURN_DURATION`, `STT_TIMEOUT` | Число без единицы (`120`) или отрицательное | Добавь единицу: `120m`, `2h`. Просто `0` выключает. |
| `SUDO_MODE must be off, env or telegram` | Опечатка | Одно из трёх. |
| `SUDO_MODE=env requires SUDO_PASSWORD` | В режиме `env` пустой пароль | Задай `SUDO_PASSWORD` или выбери другой режим. |
| `SHOW_HOOK_OUTPUT must be true or false` | Другое значение | `true`/`false`. |
| `STT_URL must be an http(s) URL like http://127.0.0.1:8000` | Нет схемы (`127.0.0.1:8000`) | Допиши `http://`. |
| `STT_MAX_SECONDS must be a positive integer` | `0`, отрицательное, текст | Положительное число секунд. |
| `TGSYNC_HOME=…: directory does not exist` | `TGSYNC_HOME` указывает на несуществующую папку | Создай её или исправь путь. |
| `.env: …` | Синтаксическая ошибка в `.env` (например, незакрытая кавычка) | Строки вида `ИМЯ=значение`, кавычки не нужны. |
| `✗ профили — профиль "…" не найден в profiles.yaml` | `DEFAULT_PROFILE` или `projects.*.profile` ссылается на несуществующий профиль | Опиши его в `profiles.yaml` или используй `full`. |
| `✗ профили — profiles.yaml: yaml: …` | Ошибка синтаксиса YAML | Проверь отступы: пробелы, не табы. |

## Telegram

| Симптом | Причина | Что сделать |
|---|---|---|
| `✗ бот — токен не принят или Telegram недоступен`, в логе `Unauthorized` | Неверный или отозванный токен, лишние пробелы или кавычки | Скопируй токен заново в @BotFather (`/token`). |
| То же, но с сетевой ошибкой (`dial tcp`, `timeout`) | Нет доступа к `api.telegram.org` (файрвол, прокси, DNS) | С этой машины должен работать `curl -sI https://api.telegram.org`. Стандартная `HTTPS_PROXY` учитывается. |
| `✗ группа с темами — группа … недоступна: бот не добавлен или неверный GROUP_CHAT_ID`, в логе `chat not found` | Бота нет в группе или id неверный/устарел | Добавь бота в группу. Узнай id **после** включения тем: при переходе в супергруппу он меняется. |
| `✗ группа с темами — в группе не включены темы (Topics)` | Темы выключены | Настройки группы → Темы → включить. Потом перепроверь id. |
| `✗ права бота — сделай бота администратором с правом «Управление темами»`; `run` падает с `бот должен быть администратором группы с правом «Управление темами» (can_manage_topics)` | Бот — обычный участник или право выключено | Администраторы → бот → включи **«Управление темами»**. |
| `✓ права бота — управление темами есть; стоит добавить …` и сообщение `🔧` в теме управления | Нет желательных прав | Добавь «Закрепление сообщений», «Изменение профиля группы», «Удаление сообщений» ([setup 2.3](setup.md#23-бот--администратор)). |
| Нет закреплённой карточки | Нет права «Закрепление сообщений» | Добавь и перезапусти ноду. |
| Пустые темы закрываются, а не удаляются; 🧹 Уборка только закрывает | Нет права «Удаление сообщений» | Добавь его. |
| В логе `409 Conflict: terminated by other getUpdates request` | Один токен у двух процессов: сервис и `./bin/tgsync run`, сервис и Docker, две машины или `getUpdates` через curl | Останови лишний. `pgrep -a tgsync` покажет локальные процессы. У каждой машины свой бот. |
| В логе `429 Too Many Requests` / `retry after N`, сообщения приходят с задержкой | Лимит Telegram (много правок или сессий одновременно) | Ничего делать не надо: нода ждёт и повторяет (до 5 минут на вызов, правки статуса пропускаются раньше). Если это постоянно — уменьши `MAX_PARALLEL_SESSIONS`. |
| `control topic: …` при старте | Не удалось создать или переименовать тему управления | Обычно права или выключенные темы; выполни `tgsync check`. |
| Пропала тема General | tgsync скрывает её один раз при первом старте | Список тем группы → показать General. Повторно она не скрывается. |
| Не найти тему управления или её удалили | Много тем или тема удалена | Напиши `/control` в General: каждая нода ответит ссылкой на свою тему и создаст её заново, если нужно. |

## Бот молчит

На сообщения в группе нет вообще никакого ответа.

1. **Твоего id нет в списке.** Сообщения от тех, кого нет в `ALLOWED_USER_IDS`, игнорируются без ответа и без записи в логе. Сверь свой id от @userinfobot с `.env`.
2. **Нода не запущена.** Проверь состояние сервиса (setup 8.1) и лог.
3. **Не та тема.** Нода отвечает только в своих темах: теме управления `🖥 <NODE_NAME>` и темах своих сессий. В теме другой ноды и в General (кроме `/control`) она молчит.
4. **Не та группа.** Все чаты, кроме `GROUP_CHAT_ID`, игнорируются. Если создал новую группу — обнови id.
5. **Сообщения от ботов игнорируются** — в том числе от ботов других нод и сообщения «от имени группы» (анонимный администратор). Отключи анонимность в своих правах администратора.
6. **Токен держит другой процесс** (`409 Conflict` в логе): обновления забирает старая нода где-то ещё.
7. **Обычный текст в теме управления** агенту не уходит: используй `/menu` или `/new <проект> <задача>`. Текст попадает к агенту только в темах сессий.
8. **Telegram недоступен** с машины: в логе сетевые ошибки, нода повторяет попытки.

## Claude Code

| Симптом | Причина | Что сделать |
|---|---|---|
| `✗ claude CLI — claude не найден в PATH; установи Claude Code или задай CLAUDE_CLI_PATH` | Не установлен или его нет в `PATH` оболочки или сервиса | Установи Claude Code. Затем либо перезапусти `make install` из оболочки, где работает `claude --version` (unit запоминает этот `PATH`), либо задай `CLAUDE_CLI_PATH=/home/user/.local/bin/claude`. |
| В терминале работает, в сервисе нет | `PATH` сервиса записан до установки `claude`, `node` или до смены версии Node (nvm, asdf) | Перезапусти `make install` из текущей оболочки или задай `CLAUDE_CLI_PATH`. |
| Windows: `найден claude.cmd (обёртка npm), он не запускается` | Claude Code установлен через npm | Поставь нативным установщиком (`irm https://claude.ai/install.ps1 \| iex`) или задай `CLAUDE_CLI_PATH` к `claude.exe`. |
| Windows: `claude.exe не найден в PATH` | Не установлен или не в `PATH` твоего сеанса | Установи, перезайди в систему, запусти установку ещё раз. |
| `✗ claude CLI — … --version: …` | Бинарник есть, но не запускается | Выполни `claude --version` сам и исправь то, что он пишет. |
| В теме сессии: агент не авторизован / `Invalid API key` / `Please run /login` | Claude Code не залогинен под пользователем сервиса | Запусти `claude` под этим пользователем и `/login`, или `claude setup-token` и `CLAUDE_CODE_OAUTH_TOKEN=…` в `.env`. Перезапусти ноду. |
| `❌ Процесс claude завершился во время хода` | `claude` упал или его убили (нехватка памяти, идёт обновление) | Напиши ещё сообщение, чтобы продолжить. Проверь память, уменьши `MAX_PARALLEL_SESSIONS`. |
| `⏸ Нода перезапустилась во время хода` | Перезапуск сервиса или обновление | Напиши сообщение, чтобы продолжить. |
| Сессия после простоя отвечает с задержкой в несколько секунд | `IDLE_TIMEOUT` погасил процесс `claude`, он поднимается заново | Так и задумано. Увеличь `IDLE_TIMEOUT` или поставь `0`. |
| MCP-сервер в статусе `needs-auth` | OAuth не проходит без браузера | Авторизуй один раз в интерактивном `claude` на этой машине. |
| Hooks падают (сообщения `🪝`) с `command not found` | Нужного инструмента нет в `PATH` сервиса | Перезапусти `make install` из оболочки, где он есть, или выключи hook в [профиле](configuration.md#profilesyaml). |
| `/history` пустой | История лежит в другом месте | Если у Claude Code нестандартная папка, задай `CLAUDE_CONFIG_DIR` в окружении сервиса. |
| `эта сессия уже открыта в другой теме` | Сессию, у которой уже есть тема, пытаются открыть ещё раз | Пиши в существующую тему. |
| Уведомления о лимитах подписки | Лимиты Claude | `/usage` покажет окна; дождись сброса. |

## Сервис не запускается

| Симптом | Причина | Что сделать |
|---|---|---|
| `make install` пишет `Запущен другой процесс tgsync` | В терминале работает `./bin/tgsync run` или остался лишний процесс | Посмотри `pgrep -a tgsync`, останови (`pkill -x tgsync`), запусти снова. |
| `make install` пишет `Заполни … .env и запусти make install ещё раз` | `.env` не нашёлся, в папку ноды положен шаблон | Заполни этот файл и запусти `make install` ещё раз. |
| `make install` пишет `Исправь ошибки выше` | `tgsync check` нашёл ошибки | Исправь строки с `✗`. |
| `Нет Go и нет готового tgsync рядом со скриптом` | Нет ни Go, ни бинарника из релиза | Поставь Go или возьми архив релиза. |
| `systemctl --user` пишет `Failed to connect to bus` | Нет пользовательской сессии (например, `su` или SSH без login-сессии) | Зайди напрямую по SSH этим пользователем или `export XDG_RUNTIME_DIR=/run/user/$(id -u)`. |
| Linux: нода останавливается после выхода из системы | Выключен linger | `sudo loginctl enable-linger "$USER"`. Проверка: `loginctl show-user "$USER" -p Linger`. |
| Сервис перезапускается каждые 5 секунд | Фатальная ошибка при старте (права, конфиг, база) | Причину покажет `journalctl --user -u tgsync -n 50`. |
| `migrate: …` или `database is locked` | База скопирована на ходу, диск полон или два процесса на одной базе | Останови все процессы tgsync, проверь место на диске; если база повреждена — восстанови из копии. |
| `sudo: сокет …: …` | Не удалось создать `askpass.sock` (старый файл, права) | Останови ноду, удали старый `askpass.sock` в папке ноды, запусти снова. |
| macOS: `launchctl print` ничего не показывает | Агент не загружен | Ещё раз `make install`; смотри `~/Library/Logs/tgsync.log`. |
| macOS: нода засыпает ночью | Mac уходит в сон или ты вышел из системы | Оставайся в системе, отключи сон. |
| Windows: `running scripts is disabled on this system` | Политика выполнения скриптов | Запускай ровно так: `powershell -ExecutionPolicy Bypass -File scripts\install.ps1`. |
| Windows: задача в состоянии `Ready`, процесса нет | Цикл падений или ты не залогинен | Читай `%APPDATA%\tgsync\tgsync.log`, запусти exe с `check`. |
| Windows: после `Stop-ScheduledTask` старая нода продолжает отвечать | Дочерний `tgsync.exe` пережил задачу | `Get-Process tgsync \| Stop-Process`. |

## Разрешения и sudo

| Симптом | Причина | Что сделать |
|---|---|---|
| Агент выполняет команды без вопросов | Автоодобрение 🟢 или 🟡 (`/approve`), сработало правило «Всегда», команду разрешают твои настройки Claude Code (`permissions.allow`, `defaultMode`) или режим сессии `acceptEdits` (`/mode`) | Переключи `/approve` на 🔴; проверь `~/.claude/settings.json` и `.claude/settings*.json` проекта; `/mode default`. |
| Ход будто завис, кнопки не видно | Запрос выше по ленте темы или в теме другой сессии | Пролистай тему сессии; `REMIND_EVERY` пришлёт напоминание о неотвеченном запросе. Пока запрос ждёт тебя, `STALL_WARN` не срабатывает. |
| Кнопки не реагируют | Тебя нет в `ALLOWED_USER_IDS` или нода перезапустилась и запрос устарел | Проверь id; повтори действие. |
| `✓ sudo — SUDO_MODE=off: команды с sudo отклоняются`, и sudo отклоняется | Так по умолчанию | Включи режим ([configuration → sudo](configuration.md#sudo)) или используй `NOPASSWD`. |
| `✗ sudo — SUDO_MODE=telegram: дай боту право «Удаление сообщений», иначе пароль останется в чате` | Без права пароль не удалить | Дай право. |
| `✓ sudo — недоступен на Windows, SUDO_MODE принудительно off` | На Windows sudo нет | Так и задумано. |
| sudo спрашивает снова / «incorrect password» | Неверный или сменившийся пароль | До 3 попыток на вызов. Для режима `env` обнови `SUDO_PASSWORD`. Осторожно с блокировкой `pam_faillock`. |
| sudo падает с `a terminal is required` | `sudo` вызван не прямо в одобренной команде (например, внутри скрипта, который написал агент) | Токен получают только вызовы `sudo`, записанные прямо в одобренной команде. Попроси агента вызвать `sudo` явно. |
| Команды с путём к папке tgsync всегда требуют кнопку, даже в 🟢 | Так задумано: tgsync защищает свои файлы | См. [security.md](security.md). |

## Голосовые

| Ответ в теме | Причина | Что сделать |
|---|---|---|
| `🎙 Распознавание не настроено (STT_URL).` | `STT_URL` пустой | Задай и перезапусти ноду ([configuration → голосовые](configuration.md#голосовые-сообщения)). |
| `🎙 Голосовые работают в теме сессии.` | Голосовое отправлено в тему управления | Отправь в тему сессии. |
| `🎙 Слишком длинное: N с, максимум M с.` | Длиннее `STT_MAX_SECONDS` | Подними лимит или разбей на части. |
| `⚠️ Аудио больше 20 МБ …` | Telegram не даёт ботам скачивать файлы больше | Запиши покороче. |
| `⚠️ STT: … connection refused` | Сервер распознавания не запущен или слушает другой адрес | `docker compose -f deploy/stt/compose.yaml ps`; `curl http://127.0.0.1:8000/v1/models`. Если нода в Docker, `127.0.0.1` — это сам контейнер: укажи адрес хоста. |
| `⚠️ STT: HTTP 404: …` / модель не найдена | Модель не скачана или `STT_MODEL` другая | `curl -X POST http://127.0.0.1:8000/v1/models/Systran/faster-whisper-small` или исправь `STT_MODEL`. |
| `⚠️ STT: context deadline exceeded` | Распознавание дольше `STT_TIMEOUT` (первый запрос ещё и загружает модель) | Повтори; подними `STT_TIMEOUT` (например, `180s`); возьми модель поменьше или GPU. |
| `⚠️ STT: непонятный ответ сервера` | `STT_URL` указывает не на STT API, совместимый с OpenAI | Укажи корень сервера, без `/v1`. |

## Файлы

| Сообщение | Причина | Что сделать |
|---|---|---|
| `…: файл вне папки проекта` / `ссылка ведёт за пределы проекта` | `/file` отдаёт только файлы внутри проекта | Скопируй файл в проект. |
| `…: служебный файл tgsync не отправляется` | `.env` и база не отправляются никогда | Так и задумано. |
| `… МБ, больше лимита Telegram 50 МБ` | Лимит отправки для ботов | Сожми или разбей. |
| `файл больше 20 МБ — лимит Telegram для ботов` | Лимит скачивания файлов, которые шлёшь ты | Пришли файл поменьше или положи его на машину другим способом. |
| В конце хода не пришли ожидаемые файлы | Не подходят под `AUTO_SEND_GLOBS` или их больше 5 за ход | Поправь маски; бери файлы кнопками или `/file путь`. |

## Docker

| Симптом | Причина | Что сделать |
|---|---|---|
| `set TGSYNC_UID=$(id -u)` | Не переданы переменные | Начинай команду с `TGSYNC_UID=$(id -u) TGSYNC_GID=$(id -g)`. |
| `set PROJECTS_ROOT in the env file` | compose не получил env-файл | Добавь `--env-file ~/.config/tgsync/.env`. |
| Ошибка монтирования `~/.claude.json` или он стал папкой | Файла не было | Удали созданную папку, `touch ~/.claude.json`, запусти снова. |
| Агент в контейнере не авторизован | Хост на macOS (Связка ключей) или на хосте нет входа | `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN=…` в `.env`. |
| Hooks падают с `command not found` | Инструмента нет в образе | Пересобери с `--build-arg EXTRA_PACKAGES="…"`. |
| Нет прав на файлы проекта | Пользователь контейнера не владелец файлов | Используй свои `id -u`/`id -g`; файлы должны принадлежать тебе. |
| `409 Conflict` | Параллельно работает сервис systemd | `systemctl --user disable --now tgsync`. |
